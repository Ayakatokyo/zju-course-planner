## 发现、修复和保留的失败

1. 首次真实四轮全部有结果，但旧脚本把第三轮合理的 `validate/fail` 当成“没调用 generate”。保留原回执；独立业务评价 v2 重新核对双锁、硬周五、实际冲突和计算一致性，四轮通过。未把离线复评写成再次调用模型。
2. 浏览器复测中，生成可行后又校验通过，旧程序仅认最后工具，导致 `inconsistent_outcome`。失败最终原文未留存，不猜测具体模型字段。现改为按 outcome 选择相应工具的最新有效证据，核对最终条件；同条件同班次出现后续矛盾则拒绝，其他组合的失败另行提示。实际页面已复测成功。
3. 中间一次真实 API 最终格式被拒绝为 `invalid_final_decision`；验收脚本又因决策为空崩溃，完整合成响应已保存但原始回执未写出。现只允许一次有界格式纠正，不重新执行工具、不扩预算、不放行权限/版本/矛盾错误；脚本先写基础回执再评价，评价异常保持失败。反例回归已覆盖。最终四轮没有触发格式纠正，不能把它写成该分支已获真实服务验收。

中间205项通过证据保留为 `chat_live_20261013_*`，不能代替修复后的213项。模型输出具有变化性，本轮有限样例通过不证明任意自然语言都可靠。
