# 浙大教务助手：开发历程与后续规划

更新：2026-10-23。用途：介绍网页的内容底稿。本文件保留开发历史，未来规划改以部署、并发治理、账号权限、对话持久化及运维工程为主。**规划尚未实施，不代表已有并发容量、线上服务或完整业务验收。**

## 1. 项目如何发展到现在

项目围绕一个连续需求展开：学生用自然语言查询本人教务信息，再把培养要求、课程偏好和时间条件转成可以比较、锁定和调整的课程方案。研发过程先厘清数据与权限，再接入真实来源，最后通过实际对话修复范围、条件和解释问题。

| 阶段 | 遇到的问题 | 主要工作与阶段产物 | 当时及当前边界 |
|---|---|---|---|
| 2026-10-09：需求与数据底座 | 样本、课程、修读记录、认定规则容易混淆；输入学号不能证明身份 | 保留原始交接输入；建立模块、字段、本人权限及确定性计算设计；形成独立 synthetic 开发底座 | 当时尚无真实学校接入；23 条候选规则仍需审核，不能把样本当正式规则 |
| 2026-10-13：模型与推荐原型 | 有计算功能，但自然语言尚不能形成完整操作入口 | 接通真实 DeepSeek 响应，完善工具调用与推荐能力线；形成课程参考与检索准备 | 模型调用成功与合成对话成功，均不代表本人业务验收 |
| 2026-10-14—15：本人登录与教务入口 | 真实资料分散，字段、空值和来源含义不一致 | 完成学校本人客户端登录与取数实践；建设成绩、课表、考试和培养方案辅助页面；收口已验收的取数方向 | 本机本人登录已有实践；学校正式应用 SSO 许可另行未确认 |
| 2026-10-15—16：真实问答与来源链路 | 空缓存被当无记录、分页不完整、范围误称和引用不足 | 建立当轮取数、本人培养原文检索、范围/未知投影及一次有界格式修复；后续接入本地语义检索 | 记录存在不等于已获学分；引用存在不等于每句话准确 |
| 2026-10-16—20：连续课程组合 | 生成后锁课、软硬条件调整和只读追问不稳定 | 打通获准学期历史课程组合、保留条件重算、保存结果查询与解释；区分来源受阻、条件无解和执行预算不足 | 有限真实旅程取得支持；完整培养适用、最新开课/余量和正式推荐尚未验收 |
| 2026-10-21：体验与职责收敛 | 重复取数、正文冗长、页面过程区过多、协议复杂 | v24—28 优化近期问答、取数与简洁界面；统一 AcademicHarness；v29—31 改进候选解释、上下文和回答协议 | 保留自然语言主入口与一行等待状态；底层日志保留，页面不恢复已移除的过程/依据入口 |
| 2026-10-22：常用旅程修复 | 新旧方案引用混用、复合保留句误拒、解释超出证据 | v32—34 修复门数、锁课、初次周五偏好、当前引用与否定保证句；完成若干真实生成→调整→比较旅程 | 原失败仍保留；语义、正式培养适用/推荐与整体用户体验仍未验收 |
| 2026-10-22—23：展示交付与布局 | 需要把工程成果解释给不了解项目的人 | 整理真实账号截图、操作视频、源码与介绍材料；10月23日对话区加宽、首页输入框居中，重新取材并补充工程化路线 | 展示包供用户制作网页；本次没有部署网站或接入 Redis |

时间线依据[开发进度](开发进度.md)第 7、12—14、39—64、66—80、83—102 节整理，按真实记录归并，不补造精确工时。各阶段成功与失败、工程检查与本人实测分别记录；不能把不同版本的通过数累加成准确率。

## 2. 当前可以怎样介绍

**已经实现并有有限实测：** 本人登录及教务查询、实际 Flash 问答、培养原文检索、获准学期历史课程组合、保留门数/学分/锁定的调整、方案比较和简洁对话页面。

**已经发现、仍需优化：** 答复偶尔冗长或重复；依据概况推断具体课程情况、由课程名推断方向、把返回方案集合扩大成候选全集；格式修复与等待仍可能发生。现有来源、授权、条件和版本检查必须保留。

**尚未完成：** 正式培养适用与学业认定、真实可选资格/余量与完整时间信息、完整语义和用户体验验收、生产多人负载验证、Redis 接入及公网部署。

本项目仍是本机单 Python 服务、原生网页、SQLite 与本地私有资料，模块并非独立微服务。当前架构见[职责收敛后的架构](项目架构_职责收敛后_20261021.md)，真实 v34 边界见[安全回执](../validation/dialogue_v34_real_20261022_acceptance.json)。

## 3. 下一阶段优先做什么

| 阶段 | 工程方向 | 交付判断 |
|---|---|---|
| D0 | 静态项目介绍站 | 展示功能、架构和操作；素材公开范围经确认后再发布 |
| E1 | 可重复部署 | 生产入口适配、容器、HTTPS、环境配置、健康检查与回滚可复现 |
| E2 | 账号与对话存储 | 可信绑定、本人隔离、历史分页、请求幂等和重启恢复可验证 |
| E3 | Redis 与并发治理 | 限流、有界队列、租约及派生缓存按实际瓶颈引入；容量有测量依据 |
| E4 | 持续运维与试点 | CI/CD、监控告警、成本配额、备份恢复、依赖故障处理和受控放量 |
| 持续维护 | 现有对话质量 | 维护准确性、简洁性及条件/版本约束；完整语义与正式推荐仍单独验收 |

优先级表示依赖关系，不是已承诺工期。公开介绍页可独立于在线教务后端推进；不为展示技术栈一次性重构。Redis 不能消除学校连接的进程归属问题，数据库存储不能替代本人鉴权，已有会话保存也不等于生产历史管理已完成。

## 4. 网页可以直接采用的规划文案

> 下一阶段将建设可部署、可管理、可恢复的教务服务：完善网站部署、账号权限和对话持久化，通过 Redis 管理限流、队列与共享状态，并补齐发布回滚、监控告警、成本预算、备份恢复和容量验证。各项按阶段验收后逐步开放试点。

网页将开发历程压缩成 4—5 个里程碑，功能与当前架构优先；工程规划用四张主卡加运维补充卡，对话体验仅作一项持续维护。用“已实现 / 待验证 / 规划中”标签区分当前与未来，不写“Redis 已上线”“已支持某并发量”等无证据结论。

本包真实账号图片和视频是用户私用制作素材；本次按用户最新要求保留登录学号，密码保持隐藏。制作网页不自动授权公开发布个人素材。

详细实施步骤与验收标准以[工程化建设与上线规划](工程化建设与上线规划_20261023.md)为准；[旧版系统优化路线图](系统优化与公开部署路线图_20261022.md)保留历史建议，其体验优先排序不再作为本版展示重点。
