## 第一步的接口

所有来源共用以下表示；正文由模型直接组织，服务端不再要求模型选择来源专属的回答模板：

```json
{"kind":"answer","text":"给用户的中文正文","evidence_ids":["本轮实际来源ID"]}
```

`kind`为`answer`、`clarify`或`not_ready`，问候也用模型自己的正文。只有澄清可附`request_basis`以保留已有待补请求的归属。通用问候可以没有引用；已读本人资料的回答仍需有效来源。保留敏感信息检查、过期/外来引用拒绝及方案版本核对。表格和方案值由实际工具结果生成；正文不会因为引用有效而被宣称逐句正确。

旧历史会话只做展示兼容，不保留旧协议作为新模型输出的第二套通道。当前旧协议测试需要迁移或按已退休的模板行为明确替换，不能以兼容旧测试为理由继续让模型使用旧协议。

本轮开始前已将108份业务源码、页面与测试保存到Git忽略的本机快照，随后补存原UI验证夹具，作为本轮差异核对基点；未复制运行数据库、来源原文或凭据。上一轮v29/v30与本轮改动均未提交、推送。
