# 基于秋冬样例的 RAG 首版范围与数据缺口

日期：2026-10-13。状态：当前批次上的实施设计，尚未建立新PDF检索索引、调用Embedding或完成真实原文生成问答。继承[RAG权限、引用与评估契约](RAG检索权限引用与评估设计_v1.md)，应用模型状态以最新开发进度为准：DeepSeek合成工具对话已经验证，旧设计中的“无模型闭环”属于历史状态。

## 1. 结论和数据基线

用户已确认这批秋冬数据足以作为课程样例。可以进入真实语料RAG设计及首版实施，不必继续扩大采集或补齐春夏数据。当前阻碍主要是语料加工、适用范围/许可映射、引用和评估，不是缺少更多同类文件。

- 培养依据：2026级目录162项、PDF162份、2,161页，已取得原件、提取文本与页定位；解析通过不等于表格/附注/图示语义或规则效力已审核。
- 开课样例：2026—2027秋冬、用户指定12个账号可见范围，2,177个课程代码组、2,597条分类内记录、6,187条班行观察；作为带观察时间的批次，不能作为实时余量或全校可选性事实。
- 运行索引仍是原JSON的54块参考切片；新增162份PDF和开课样例尚未导入运行时。现有DeepSeek聊天接入不等于新增语料RAG或Embedding已经接入。
- 跨类、搜索引擎、研究生课程均由用户排除，不再列本轮数据补采依赖。原inputs不改，23条候选仍待审核，真实数据与synthetic分开。

按用户补充的业务事实，课程池总体共享，专业基础/本类专业等板块是随专业或方案变化的查询视图。后续建立统一课程/当期班次底库，板块出现关系保留筛选上下文，个人页面状态单独存放；“账号可见”是本批次来源证据，不意味着每个账号有完全不同的课程本体库，不阻塞首版RAG。实际重叠统计见[课程池与板块重叠核验](课程池与板块重叠核验_20261013.md)。

2026级培养方案的要求归属与当期开课仍是不同关系。必修、模块计入等属性挂在方案版本/要求节点与课程的关系上，不由当前板块归属变成课程全局属性。课程存在、板块展示、满足方案要求和本人能否选分别处理；浏览指定方案不建立本人适用绑定。课程代码关联核对来源代码体系，不按同名自动合并；同一课跨板块保留多条来源关系，避免重复实体或重复向量放大检索权重。

## 2. 首版能力与数据分工

| 问题 | 首版处理方式 | 能给出的结论 |
| --- | --- | --- |
| 指定2026方案某模块要求多少学分、有哪些附注 | PDF结构化分块＋范围过滤检索＋带页码引用回答 | 该文档原文的要求；不能由模型将条文变成自动执行规则 |
| 指定课程在方案中属于哪个模块、哪里提到它 | 精确代码/名称检索结合上下文与原文定位 | 文档出现位置与上下文；映射冲突明确显示 |
| 这批秋冬样例里某课程有哪些教师/时间/地点 | 结构化课程与班行查询工具 | 该采集批次的观察结果和unknown；不靠向量检索精确列举全部班次 |
| 方案提到的某课在这批样例中是否有开课观察 | 先检索方案依据，再按已核验代码映射查结构化批次 | 找到对应观察，或“本批次未查到/映射未确认”；不推成学校未开课 |
| 某课程适不适合兴趣、教学内容/难度如何 | 仅在已取得课程说明或依据足够时回答 | 只有课程名/教师/学分时，不推断课程内容、难度或教学评价 |
| 我还缺多少学分、我能否选、能否无冲突毕业 | 后续本人事实与确定性工具 | 当前真实本人数据/规则/周次不足，不能给正式通过结论 |

Agent对话继续是入口。依据检索、结构化查询与确定性计算由服务端受限工具分工；后续调整仍继承锁定、固定项与输入版本，再计算和校验。

## 3. 数据缺口：按能力判断是否阻塞

| 缺口 | 影响 | 是否阻塞首版指定方案问答 |
| --- | --- | --- |
| PDF表格/跨页表头/例外/图示的准确解析及精确定位 | 容易丢失否定、学分单位或条件，引用不支持结论 | 是，至少首版纳入的片段必须可核对；无需先人工逐页审核全部162份 |
| 方案年级/专业/方向/版本和源权限元数据 | 可能串方案、错误适用或超范围读取 | 是，纳入部分必须具备明确范围；未知值不能当通配 |
| 代表性问答及相关证据标签 | 不能判断检索是否找对、回答是否有依据 | 是，实施时同步建立；这属于评估数据，不需要再爬课程 |
| 课程大纲、内容/考核/可靠先修细则 | 影响课程内容介绍、兴趣匹配与先修判断 | 不阻塞培养原文问答；对应问题标明缺依据 |
| 配套认定/替代/重复修读/选课通知等文件 | 影响具体政策例外和执行规则 | 不阻塞已覆盖条文问答；按首版失败问题定向补来源 |
| 本人适用方案、修读/成绩/认定、当前正式安排及可信授权 | 影响个性化学业分析与真实推荐 | 不阻塞获准本机参考浏览；阻塞真实本人结论 |
| 精确周次、校历/节次、考试及跨刷新稳定班身份 | 影响真实冲突计算、持续更新与方案重校验 | 不阻塞依据问答和批次开课查询；阻塞完整真实排课校验 |

后端unknown清单明确：6,187条观察没有已验证的周集合/校历版本；考试时区未核验；先修标志不等于权威先修规则；4,715个来源键组的跨刷新稳定性未核验；页面状态不等于正式中选、获分或本项目本人绑定。不能用Embedding、模型常识或synthetic值补齐。

当前规范化候选另保存5组冲突记录，需保留各自原观察和解析依据，不因同一候选来源键或较晚时间直接覆盖为唯一事实。

## 4. 首个可审核实施切片

1. **冻结资料登记。** 接受本批次作为样例版本，完成原件/页文本/方案登记/映射与哈希对齐。全部162份可登记；第一轮选3–5份具有课程表、跨页或例外条文的代表方案做精细分块。其余显式标记未纳入当前索引，避免把登记成功算成检索覆盖。
2. **构建可回查块。** 以章节、要求条款和课程表行分块，携带标题、单位、适用条件、表头/脚注；跨页保留全部物理页定位。原文、清理文本和建模解释分别保存；图示提取不可靠时不作为已核验文字依据。
3. **固定权限和范围。** 现有材料按获准本机参考域处理，不直接转匿名共享库，也不进入mock学生工作区。检索前过滤访问域/源许可/方案/年级/方向/版本，返回引用时再次核验。本人绑定和生产权限继续独立实施。
4. **建立检索对照。** 保留精确课程代码和词法基线，同时可开始本地Embedding实验，比较词法、向量与混合结果。模型、维度、分块、索引均版本化；不预设向量方案一定优于关键词，也不需要先训练专用模型。具体Embedding型号和依赖在实验实施时核验并选择，本轮未安装或运行。
5. **补评估数据。** 首批设计约40–60题，覆盖精确代码、自然语言同义、表格/例外、跨页、跨方案误命中、语料无依据及未知适用范围。相关证据和预期unknown需人工核对；同一问题的改写不跨开发/保留集。分别评估召回、引用定位/支持、回答正确性及拒绝越权，不能只数返回了多少答案。
6. **接入带引用回答。** 先确认本地检索和引用回查，再接对话工具。现有DeepSeek已验证的是synthetic工具链；真实学校原文出站许可没有随API配置自动取得。可先本机检索/展示，生成服务和允许发送的非个人片段范围单独确定后再实测语义回答。

索引优先沿用来源登记与SQLite；向量存储按小规模实验需要选择，不预先引入复杂平台。先保留源版本和证据可回查，个人检索缓存暂不实现；后续缓存必须绑定权限、用途、语料和索引版本，命中仍重新授权。

## 5. 本阶段交付与验收

交付首版语料清单、块与引用映射、字段/覆盖缺口、评估集和检索对照，以及通过授权后的真实原文引用问答证据。展示必须明确本次已纳入哪些方案、哪批开课数据，引用可打开原页/表行，无依据与未知是正常结果。回答引用的存在不代替“引用内容支持回答”的核验。

进入设计与本地实验不要求先补齐真实个人数据；真实推荐上线前才必须完成对应本人/规则/计算依赖。当前阶段不能将已有真实DeepSeek对话或213项历史测试写成新PDF RAG验收通过。本轮仅核对设计、代码入口与批次清单并更新文档，未调用模型/Embedding、未改业务代码或原始数据、未提交推送部署。
