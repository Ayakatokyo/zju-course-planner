# 本地运行与开发指南

本文承接 [README](../README.md) 中的使用入口，记录当前源码支持的配置。真实业务能力与验收以[开发进度](开发进度.md)为准，历史设计不代表当前已完成能力。

## 环境与入口

基础服务使用 Python 3.10+ 标准库和 SQLite，不需要安装前端依赖。Node 用于部分网页合同测试与 JavaScript 语法检查，不是应用运行依赖。本地 Embedding 使用另外配置的私有编码器环境。

所有命令在仓库根目录执行。查看参数不会启动服务：

```sh
python3 -m course_assistant.server --help
```

| 入口 | 命令 | 默认数据位置 |
| --- | --- | --- |
| 本人教务 | `python3 -m course_assistant.server --enable-school --port 18875` | `private/school_app/planning.sqlite3` |
| 基础合成演示 | `python3 -m course_assistant.server --enable-mock --port 8765` | `runtime/planning.sqlite3` |
| 独立推荐演示 | `python3 -m course_assistant.server --enable-mock --recommendation-demo --port 18865 --db runtime/recommendation_demo.sqlite3` | 显式指定的演示数据库 |

上表的旧 `--enable-mock` 演示仍单独运行；下述配置型模拟账号则与学校账号共用主应用及数据库，通过 realm、owner 和会话绑定隔离。学校或配置型模拟账号的自定义 `--db` 应位于项目外、`private/` 或 `local-only/`；相关目录不得提交。未启用任何身份来源时个人 API 不开放；学校登录失败不会降级为模拟身份。

服务固定监听 `127.0.0.1`，按 `Ctrl+C` 退出。已有服务和登录会话应继续复用，不为阅读文档或开发交接重启。停止服务会丢失内存中的学校连接，需要重新登录；现有历史记录不保证在新的认证代次下继续可用。

## 统一登录中的模拟账号

主应用可同时启用学校账号和已有审核模拟账号：

```sh
python3 -m course_assistant.server --enable-school --port 18875 \
  --scenario-bundle /本机私有目录/scenarios.json \
  --scenario-accounts /本机私有目录/accounts.json \
  --scenario-pdfs /本机私有目录/pdfs.json
```

三个 `--scenario-*` 参数须一起配置。bundle 是既有审核场景；accounts 保存模拟账号的加盐密码哈希与学生绑定；pdfs 是培养方案 key 到本机 PDF 路径的 JSON 映射，文件摘要须与审核场景一致。真实个人资料、PDF 路径映射和测试凭据均不提交。不要对运行中的18875直接重复启动；更新该进程会清空学校内存连接，须遵守已有登录保留要求。

两类账号都走 `/api/auth/login` 和相同 Cookie/CSRF 会话。学校验证由学校数据提供层完成，配置型模拟账号由本机数据提供层验证，登录失败不会切换来源。登录后共用 PersonalChatService、AcademicHarness、PersonalObservationStore、PersonalEvidenceService、模型设置、草稿、历史和查询页面；模拟提供层不另写 Agent 或查询算法。未提供的课表/考试返回未就绪，不能解释为零条或空闲。原独立 scenario 服务及 `--enable-mock` 仅保留历史兼容，不是统一入口的执行链路。

2026-10-25统一主应用当前为 [18875](http://127.0.0.1:18875/)（v41/PID90346），18882临时候选已停止，学校已按用户授权登录。两个专业模拟账号连续Flash与主查询页面、本人四轮成绩/培养问答和指定历史课程的生成/锁课/只读比较已分别有限核对；不等于正式推荐或整体语义验收。旧培养方案与当前课号对应按用户要求暂缓。保留当前登录，不为交接重启。详见开发进度第113—117节。

## 模型配置

参照根目录 [.env.example](../.env.example)，在本机 `.env` 中设置：

```dotenv
DEEPSEEK_API_KEY=你的_API_Key
DEEPSEEK_MODEL=deepseek-flash
COURSE_ALLOW_REFERENCE_TEXT=false
```

当前项目实测固定使用 `deepseek-flash`。程序只读取约定字段，不执行 `.env` 内容；同名进程环境变量优先于文件。可用 `--model-env-file` 指定另一个本机配置文件。配置在服务启动时加载；需要重新加载时，先安排好正在使用的会话，再停止并启动服务。

学校本人对话的新会话默认开启深度思考，可在输入区关闭；模型选择位于发送按钮旁。登录、刷新和切换模型不会自动提交业务问题。答案界面只呈现核心结果和必要限制，等待时展示一行状态；底层日志与实际模型输出保留在私有数据中，不恢复旧“处理过程”“运行记录”等入口。

学校本人对话发送的是问题和经允许字段筛选后的必要相关材料。`COURSE_ALLOW_REFERENCE_TEXT` 仅控制原合成推荐 / 独立参考分支的非个人原文发送，默认关闭；它不能授权发送个人材料，也不能关闭学校本人对话已经采用的相关资料发送策略。

## 可选的本地课程与检索配置

以下设置是**服务进程的环境变量**，根目录 `.env` 解析器不会读取它们。请在本机私有启动环境配置，不把真实路径或数据提交到 Git。

| 环境变量 | 用途与前提 |
| --- | --- |
| `COURSE_CATALOG_DELIVERY_INDEX` | 指向经核验的本地课程交付索引 JSON，只开启课程名称 / 代码参考 |
| `COURSE_DATA_TEST_DELIVERY_INDEX` | 指向获准历史班次交付索引；需要通过完整性校验 |
| `COURSE_DATA_TEST_TERM` | 与上一项同时设置；当前实现仅允许已核验的 `2026-2027-AW` |
| `COURSE_SEMANTIC_ENCODER_MANIFEST` | 可选本地语义编码器的清单路径 |
| `COURSE_SEMANTIC_PYTHON` | 可选编码器使用的独立 Python 运行环境路径 |
| `COURSE_OCR_TESSDATA` | 可选本地 Tesseract 语言目录，须同时含 `chi_sim` 和 `eng`；不经过云端OCR |

这些文件和编码器不随仓库分发。没有课程目录配置时，目录工具明确不可用，不妨碍学校本人教务页面取数；普通目录配置不会自动启用历史班次。没有可用编码器时，检索可回退词法并报告状态。完整准入条件见[本学期推荐闭环与本地语义检索](本学期推荐闭环与本地语义检索_20261016.md)。

成绩、课表、考试和培养资料按相关任务从学校接口读取；本地快照、PDF 和索引用于证据及派生缓存，不能把接口失败后的旧缓存当成最新结果。历史班次组合仅对已知条件计算，不证明正式开课、余量、本人培养适用或完整无冲突。

### 培养方案 PDF 检索与 OCR

新版源码优先用 Poppler `pdftotext -bbox-layout -nodiag` 读取文字和坐标，重建课程行；原 PDF 和未经该布局处理的文字保留。对空白文字层、明显编码损坏，或“稀疏原生文字＋较大嵌入图片”的页面尝试本机 `pdftoppm` + Tesseract OCR。正常文字版不走OCR；混合页检测使用本地pdfimages，缺失时不猜测图片内容。OCR结果带待复核标记，不能把引擎置信度当作课程学分正确率。macOS 可通过 Homebrew 安装 `poppler`、`tesseract`；中文与英文语言文件须另行配置到上述目录，缺失时返回不可用状态。语言文件、原PDF及派生证据均不入Git。

普通问题使用关键词与本地向量混合召回，明确课名/代码优先；条款保留相关模块和表头上下文。要求列举模块课程时，模型可选择 `module_courses` 并按 `next_offset` 续取，不把普通前5条检索结果称为全部课程。条件省略时可按context_request调用module_context分页取得模块条件；同次工具返回的重复上下文以证据ID及位置复用，原文留在本地。模块列举仍只覆盖成功解析的行；复杂混合页、跨页合并单元格和低清扫描仍需人工核对。页码、原文位置、坐标和处理版本留在本地证据中。

固定原文检索可用下列命令复测，不访问学校或模型。清单的 `documents` 项应包含 `id`、相对PDF路径 `pdf`、`sha256` 和 `cases`；每个用例提供 `id`、`query`、`required: [{page, text}]`，可选 `mode` / `forbidden` / `module_path` / `expect_empty`；评测同时核对检索结果和实际模型投影中的原文覆盖，不能替代最终答案语义审核。预期文字须先对照PDF原页，不能从本次检索结果倒推。清单和详细输出放入私有目录：

```sh
python3 scripts/evaluate_curriculum_rag.py /绝对路径/私有评测清单.json --output /绝对路径/私有评测输出
# 已配置本地编码器时，加 --dense 验证混合检索。
```

文档向量只缓存在当前检索实例内（最多两组语料），以编码器身份与完整输入文本作为键；原文或模型变化失效，截断计数不会因命中缓存消失。每次仍核对本人授权和当前来源。首次编码、缓存未命中及整轮模型等待不享受同一提速保证。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 页面提示未配置模型 | 检查 `.env` 的 Key 和配置文件位置；配置变更需由服务重新加载 |
| 模型返回额度或网络错误 | 检查当前账号的 API 可用性和网络；不要把失败答复当成已完成任务 |
| 无法登录或学校会话过期 | 按页面提示重新登录，验证码由本人处理；不改用 mock 访问真实数据 |
| 查询成功，但课表或考试仍有缺项 | 核对学期和学校原页面；来源缺失不表示完全空闲或没有考试 |
| 无法生成课程方案 | 检查是否已配置获准历史数据，以及范围、学分、锁定与时间条件是否有解；正常本人课表规划还依赖完整的本人安排 |
| 提示旧方案或引用失效 | 使用当前轮次的方案继续，必要时重新生成；不跳过版本检查 |
| 启动提示端口占用 | 先确认是否已有本项目服务；正在使用时打开既有地址，不直接结束占用进程 |

## 开发与验证

```sh
python3 -m unittest discover -s tests -v
node --check web/app.js
```

没有 Node 时相关网页测试会明确跳过；跳过不算通过。测试只证明其覆盖的代码行为，真实模型、学校来源、回答语义与用户体验需分别验证。

`validation/run_live_chat.py` 是独立合成工作区的真实模型验证脚本，会实际调用 API；它不属于纯离线检查，也不验证学校本人业务。其会话和回执保存在 Git 忽略的 `local-only/chat_acceptance/`。

| 目录 | 内容 |
| --- | --- |
| `course_assistant/` | 会话、学校客户端、模型工具、检索与确定性计算 |
| `web/` | 原生网页 |
| `demo/` | 独立合成夹具 |
| `tests/`、`validation/` | 回归测试与分阶段验证记录 |
| `docs/` | 产品、架构、数据说明和开发日志 |
| `inputs/zju_course_agent_handoff_v1/` | 不可改写的原始交接输入及清单 |
| `private/`、`local-only/`、`runtime/` | 不提交的本机材料、派生缓存或运行数据 |

开发前按根目录 [AGENTS.md](../AGENTS.md) 阅读适用约定，核对已有改动。执行层的阶段设计见[教务 Agent 与 Harness 架构](教务Agent与Harness架构_v1_20261021.md)，每轮开发与验证写入[开发进度](开发进度.md)。

## 执行流程

网页接收问题后，服务端先核对本人会话和可用能力。模型根据问题选择已声明的工具；执行层按本人范围获取教务资料、检索培养片段或调用确定性课程计算，将结果和来源交回模型组织答案。返回前检查引用与方案版本，页面展示答复、表格和方案。

| 分工 | 负责内容 |
| --- | --- |
| 网页与会话层 | 登录、对话历史、发送与状态展示 |
| 模型 | 理解需求、选择工具、组织解释 |
| 受控执行层 | 复核权限与范围、协调来源、执行工具 |
| 检索与计算 | 定位原文、计算学分与时间条件、生成并复核组合 |
| 状态与证据 | SQLite 保存记录，私有目录保存来源，内存持有学校连接及部分当前状态 |

这些是一个本机服务内的模块分工，不是已部署的独立微服务。模型不能代替学校认证、正式认定或确定性计算；已有引用也不等于回答语义已完全正确。

## 工程规划

以下均为后续建设方向，尚未作为生产能力交付。静态项目介绍站与可登录的在线教务服务需要分别建设和验收。

| 方向 | 下一步产物 | 验证重点 |
| --- | --- | --- |
| 部署 | 生产服务适配、版本化制品、HTTPS、配置与健康检查 | 干净环境可部署、版本可核对、失败可回滚 |
| 并发治理 | 按实测瓶颈评估 Redis 限流、有界队列和派生缓存 | 不串用户、不无限排队、不用旧缓存冒充最新来源 |
| 账号与权限 | 账号生命周期、可信绑定、跨会话历史授权 | 过期与撤销有效，所有个人资源按本人范围访问 |
| 对话持久化 | 消息顺序、请求幂等、失败恢复与归档策略 | 重复提交不重复修改，重启后状态可解释 |
| 运维与可靠性 | CI/CD、监控、调用预算、备份恢复与容量验证 | 故障可定位、恢复可演练、容量结论有实测依据 |

Redis、PostgreSQL、多进程队列和公网服务均不能由现有本机运行结果推定已实现。学校连接的内存归属与允许的认证路径需要先核清，凭据不进入共享队列或缓存；工程扩容也不会自动补齐正式推荐的业务条件。
