## 5. 真实测试、原始失败与当前完成度

同题原始请求：

> 结合我的主修成绩和培养方案，帮我从本学期已有课程数据中找出数据分析方向的候选课，给一个至少6学分的课程组合，尽量周五空闲。说明为什么选择这些课程；不核本人课表和考试，不能把未见成绩当作没学过。

1. 初始v29：5次Flash生成，已有首选与比较，但领域判断过强。四次培养检索分别向模型传入5/1/0/0片段，省略0/2/3/3，回答将后两次省略误称为无命中。
2. 上下文修补后：4次生成，执行了9次模型工具调用，仍在扩散检索，耗尽总10次工具预算后未计算，报 `turn_budget_exceeded`。
3. 预算修补后：3次生成，完成方案，但把用户最低6改成了7；来源投影一致不代表任务条件正确。
4. 学分修补后最终同题：28.63秒、3次Flash生成、4次模型工具调用，0格式修复/参数纠正/任务纠正；主修与培养各1次逻辑学校读取，课表/考试0。原最低6、无上限、软周五保持，得到7/6/6.5学分三套，周五观察占用0/1/1。

## 6. 下轮建议的工作顺序

以下是继续优化的建议，不是用户已经确认的新界面方案或扩采授权。

1. **从实际输入、上下文和最终输出定位问题。** 选取已有常见案例，看模型实际收到了哪些字段/片段、哪些省略、哪些重复、哪些是旧事实，以及回答在哪里超出证据。不要只看用户界面或只增加系统提示词。
2. **把核心回答本身做短、做清楚。** 优先尝试“直接结论/首选 → 两三个关键理由 → 有意义的备选与代价 → 一句必要限制”。成绩查询、教务解释、课程推荐分别按任务呈现；避免重新铺开诊断维度或把每个回答都套成多段报告。
3. **修正具体语义缺陷。** 两节课保持两节课；节次缺失、历史余量非正、当前余量未知分开；相关性判断必须能说明依据与推测范围。检查方案比较是否自洽，而不只校验引用存在。
4. **提高课程匹配依据。** 先检查既有获准资料能否更精准关联课名、代码、相关成绩和培养条目。课程内容/先修材料不足时保留未知；新增来源或学校端点须遵守原授权范围，不能自行扩采补全。
5. **以少量真实常用任务验收。** 用已有成绩明细/解释、教务问答、候选推荐与一个有意义续问验证下一小步。关注“有没有直接答到问题、条件是否保持、信息是否准确、文字是否简洁、是否减少无用调用”，而非增加大量边缘测试。

继续沿用Python标准库、SQLite和原生HTML/CSS/JS，优先小范围修复。若评估成熟GitHub项目，先明确其解决当前哪一个具体问题；现有讨论不等于已经授权大规模框架迁移。
