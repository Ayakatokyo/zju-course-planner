## 1. 已确认要求与待核验接入

- 学生必须先完成身份认证，才能访问本人档案、学业、个人选课、偏好及方案。姓名、学号属于标识字段，知道这些字段不构成访问权限。
- 优先使用学校获准接入的统一身份认证，由学生在学校认证页面输入学校凭据。本项目不收集、保存、记录或本地校验学校密码，也不复制学校登录页面建立自己的密码库。
- 学校官方服务说明存在统一身份认证应用接入申请流程；这不证明本项目已经获准接入，也不能据此预设 OIDC、CAS、SAML 或其他协议已提供给本项目。具体协议、回调规则、身份字段与验证材料仍待获准后核验。[浙江大学统一身份认证服务说明](https://its.zju.edu.cn/tysfrzwgr/list.htm)
- 本项目登录成功只证明经过验证的身份，不证明已获得档案、成绩或选课数据接口。个人数据源的接入许可、本人范围及实际可取得字段需另行确认。
- 官方认证尚不可接入时，可以在本地开发使用明确标注的 mock 身份与独立 synthetic 学生。它不属于校方认证；官方失败不能自动降级为 mock 成功。
- 当前 loopback 模式继续仅作 synthetic 开发演示。不得向该未实现认证的服务引入生产真实个人数据；已有 Excel、截图只用于经授权的离线字段分析，不能转为 mock 用户可查询的档案库。

## 2. 现有草稿的身份与权限缺口

以下为只读代码审查所得，当前只使用模拟数据，不能据此宣称发生真实学生数据泄露。

| 位置 | 当前行为 | 进入真实多人场景前必须改造 |
| --- | --- | --- |
| `server.py` 的 Application | 没有认证、会话或可信请求主体；demo、constraints 为全局共享状态 | 建立统一认证授权入口；活动数据与条件按本人上下文隔离 |
| `/api/bootstrap`、`/api/saved` | 通过 Store.saved() 返回所有保存方案 | 只返回当前本人可访问的记录，不能先返回全量再由页面筛选 |
| frozen_result(saved_id) | 在全部保存记录中按传入 ID 找匹配，无所有权检查 | 按对象 ID 与服务端本人键共同查找；同时验证冻结输入与来源的权限 |
| `/api/audit` 的 source 分支 | 接受请求体 student、records | 客户端内容不能充当登录身份；运行时本人数据从可信上下文取得 |
| `/api/import`、generate、validate | 操作同一活动数据或条件 | 区分本人工作区与公共资料管理；请求不能改变其他用户的状态 |
| `storage.py` 的 datasets / entities / saved_plans | 没有显式所有者、安全域或授权查询；saved() 无身份条件 | 补充资源所有权和安全域，所有读取、写入与派生输入都检查授权 |
| POST 的 Origin/Host 检查 | 提供有限跨来源检查 | 不等于登录或对象授权；会话写请求仍需要 CSRF 防护 |
| audit/planner 的 student_key 比较 | 校验计算输入归属 | 仅为业务一致性校验，不能证明请求者拥有该身份 |
| `/sources/` 与导出 | 当前只允许交接 PDF 文件名，导出可包含完整冻结数据 | 对每份来源分类；个人原文件、导出和下载必须适用同一所有权规则 |

## 3. 身份到本人资源的信任链

服务端处理顺序固定为：**验证会话 → 已认证主体 → 可信学生身份绑定 → 本人上下文 → 逐请求检查目标资源和关联输入 → 业务读取或计算。**

1. 认证结果必须由服务端按已核验的学校协议验证来源、有效期及本次认证请求的关联。用户提交的学号、截图、普通浏览器登录状态或客户端声明不能代替认证结果。
2. 主体先绑定经可信来源确认的学号与内部 student_id。学校主体标识不保证就是学号；缺少可信映射或映射有冲突时，身份可以已认证，但个人档案访问保持拒绝。
3. AuthContext 的 student_id 从会话与可信绑定推导，不从 query、JSON、表单、模型输出或页面隐藏字段中取得。StudentIdentityBinding 是身份绑定，StudentPlanBinding 是培养方案适用性，两者不能互相替代。
4. 学生即使修改输入学号、姓名、student_id、saved_id 或 snapshot_id，也不能改变本人范围。提交与本人不符的身份字段时拒绝请求，不能以它查询其他学生。
5. 新建个人资源时所有者由服务端赋值；读取或修改时以资源键和本人所有者共同查找。关联的学业快照、偏好、方案、校验结果、原文件及引用也必须全部可访问，不能只检查最外层方案。
6. 缺少规则、所有权、绑定、数据源权限或有效会话时默认拒绝。控制在服务端统一执行，不能依赖按钮隐藏、随机 ID 或前端筛选。每次请求都检查具体对象权限。[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

后台计算、未来检索及 Agent 工具只接收服务端生成的 AuthContext。模型不能自选或覆盖主体、学号、安全域和所有者；工具参数中的对象 ID 仍需授权校验。

## 4. 新增认证与授权数据对象

沿用字段字典的 string、datetime、M/U/O 约定。学号始终为字符串。以下为逻辑结构，不是数据库 DDL，也不是可直接导入的学校接口 Schema。安全身份记录不保存原始认证票据、学校密码或学校浏览器 Cookie；业务对象继续保留原有来源、版本及字段状态。

| 对象 | 核心字段 | 含义与写入者 |
| --- | --- | --- |
| AuthProvider | provider_id:M string；provider_kind:M enum(school_official/mock)；protocol:U string；configuration_version:M string；approval_status:M enum(pending/approved/disabled)；environment:M enum(local_development/official_runtime)；verification_config_ref:U string | 服务端配置。学校协议未知时为空；获准接入材料与协议验证配置分别记录；不把秘密配置写入业务响应或仓库 |
| AuthenticatedPrincipal | principal_id:M string；provider_id:M string；provider_subject:M string；auth_mode:M enum(school_official/mock)；principal_status:M enum(active/disabled)；last_authenticated_at:M datetime；verification_event_ref:M string | 服务端验证认证结果后建立；provider_id 与 provider_subject 联合标识来源主体，不能由请求体自行赋值 |
| StudentIdentityBinding | identity_binding_id:M string；principal_id:M string；student_id:U string；verified_student_number:U string；binding_status:M enum(pending/verified/conflicting/revoked)；trust_kind:M enum(school_verified/mock_fixture)；verified_at:U datetime；binding_evidence_ref:U string；binding_version:M string | 可信身份映射。缺字段、待确认或冲突时不能访问个人运行数据；mock 只绑定 synthetic 学生 |
| LoginSession | session_id_hash:M string；principal_id:M string；identity_binding_ref:U string；binding_version_ref:U string；auth_mode:M enum(school_official/mock)；issued_at:M datetime；last_activity_at:M datetime；idle_expires_at:M datetime；absolute_expires_at:M datetime；revoked_at:U datetime；csrf_secret_ref:U string | 服务端会话记录；客户端持有随机不透明凭据，服务端保存摘要。会话有效性和绑定撤销状态每次请求检查 |
| AuthContext | principal_id:M string；session_ref:M string；student_id:U string；auth_mode:M enum(school_official/mock)；security_realm:M string；role_grants:M string[]；authorization_policy_version:M string | 单次请求的服务端内部上下文，不接受客户端同名对象。student_id 为空时不能读取个人资源 |
| ResourceAccessMetadata | resource_ref:M string；data_scope:M enum(shared/student/synthetic)；owner_student_id:U string；security_realm:M enum(official_runtime/mock_development/restricted_reference)；access_policy_version:M string | 可嵌入业务记录或由所属快照提供。student/synthetic 的个人资源必须有所有者，由可信服务端上下文赋值；shared 的公共资源所有者为空，仍需明确允许访问的策略 |
| PersonalDataSourceGrant | grant_id:M string；principal_id:M string；student_id:M string；source_ref:M string；grant_status:M enum(unavailable/pending/authorized/revoked)；allowed_purposes:M string[]；valid_until:U datetime；approval_evidence_ref:U string | 记录个人数据源的接入与本人权限；认证成功不自动创建 authorized。具体数据源、连接方式及凭据方案以后另行设计 |
| SecurityAuditEvent | event_id:M string；occurred_at:M datetime；principal_ref:U string；session_correlation_ref:U string；action:M string；resource_ref:U string；decision:M enum(allow/deny/error)；reason_code:M string；policy_version:M string | 最小安全审计。相关键可使用受保护的内部引用或摘要，不记录原始会话凭据、密码和整份学业内容 |

ResourceAccessMetadata 使用字段字典统一的 data_scope 和 owner_student_id，补充安全属性，不替代 data_kind。真实 reference_sample 可能含个人信息，不因“样本”变成 shared；所有者未解决时不向运行用户开放。shared 也不等于匿名公开，需按明确公开或登录后共享策略处理。synthetic 个人资源只能绑定合成主体，不能改写 owner 后指向真实学生；derived 结果继承输入中最严格的访问范围，不能借派生、匿名内部 ID 或 synthetic 输出清除本人限制。

StudentProfile、AcademicObservation/Attempt、RecognitionRecord、StudentSubstitution、CreditAllocation、SchoolAuditReport、EnrollmentObservation、PreferenceSet、PlanVersion、ValidationResult 及其个人 SourceDocument/DataSnapshot 应具有或继承本人所有者。公共培养方案、课程定义及规则只有经明确分类后才能列为 shared；其中嵌入个人数据的部分仍受保护。AuthContext 是单次请求上下文，ResourceAccessMetadata 是公共安全属性；PersonalDataSourceGrant 只预留数据源授权记录，不设计实际连接接口。

## 5. 会话与运行模式

- 实际部署全程使用 HTTPS；会话 Cookie 设置 HttpOnly、Secure、合适的 SameSite 和受限域。会话凭据不放 URL、localStorage、导出文件、来源引用或日志。认证成功后更换会话标识，退出和过期时服务端撤销；不能只让页面清空状态。[OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
- 写操作执行会话与 CSRF 校验；学校认证回调的请求关联、重放与验证机制按最终获准协议实现，不先假定某一种协议参数足够。
- 会话有空闲和绝对到期时间，由服务端执行。具体超时值后续作为项目配置确定，不引用为校方标准；本版不规定数值。
- 绑定被撤销、冲突或版本变更时重新检查访问权，不能无限沿用旧会话中的学生声明。未认证与已认证但未绑定分别处理，后者仍不能读个人数据。
- mock 入口必须由本地开发配置显式开启，运行模式和学生均标 synthetic；不接受真实学校密码，不触达真实个人数据源，不把任意输入学号映射到真实学生。
- 官方认证失败、超时、未获接入或映射失败时，维持失败/待确认，不自动切换 mock。mock 会话不能提升为 school_official，会话与数据存储安全域不可混用。
- 当前 `127.0.0.1` HTTP 演示继续限于独立合成数据。它不能承担生产学校登录、真实档案、成绩或凭据处理；未来生产模式需完成认证授权实现和验收后另行交付。

## 6. 角色与资源矩阵

首版只需要本人访问与公共资料维护边界，不默认建立能读取所有成绩的管理员角色。角色由服务端可信配置授予，不从客户端 role 字段或模型指令中取得。

| 角色 | 登录页面 / 最小健康状态 | 已明确分类的公共培养资料 | 本人档案 / 学业 / 选课 | 本人偏好 / 方案 / 导出 | 他人个人数据 | 公共资料维护 |
| --- | --- | --- | --- | --- | --- | --- |
| 未登录 | 允许明确公开部分 | 按明确公开策略 | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| 学校已认证学生，绑定有效且数据源授权 | 允许 | 读取 | 仅本人且来源许可范围内 | 仅本人 | 拒绝 | 拒绝 |
| 本地 mock 学生 | 允许，显式显示 synthetic | 限开发安全域的非个人参考资料 | 仅本人 synthetic 夹具 | 仅本人 synthetic 结果 | 拒绝真实个人数据及其他 mock 用户数据 | 拒绝 |
| 公共资料维护者 | 允许 | 按授予范围读取 | 没有额外个人访问权 | 没有额外个人访问权 | 拒绝 | 仅授权的课程、培养方案与规则资料 |

一个主体同时是学生和公共资料维护者时，两种权限分别检查。维护者不能任意查询学号、成绩或原始个人文件；个人支持、授权委托或成绩审核不在本版范围，不能用一个宽泛管理员权限预先放开。

## 7. 当前 API 的后续改造要求

以下记录已有草稿接口应如何受保护，不新增真实检索接口。本轮没有实施这些改造。

| 当前入口 | 后续认证与授权要求 |
| --- | --- |
| GET `/api/bootstrap` | 先验证身份；只返回本人活动上下文和保存记录。公共来源另按分类过滤，不能包含别人的 frozen_dataset |
| GET `/api/saved` | 数据库查询加入 owner_student_id 和 security_realm 条件，只列本人版本 |
| POST `/api/audit` | 从可信本人上下文加载可访问输入；客户端 student/records 不作为身份。保留独立开发样本核算，但只能在 mock 安全域 |
| POST `/api/import` | 本人工作区导入与公共资料维护分别授权；服务器赋予所有者，不接受用户伪造他人所有权或修改全局活动状态 |
| POST `/api/generate`、`/api/validate` | 偏好、锁定项、当前安排及学业输入都属本人；公共班次也要符合其数据源访问范围；计算不改变身份 |
| POST `/api/save` | 方案及全部引用授权通过；新版本所有者由服务端赋值，保存不能改变 owner 或把他人版本作为前版 |
| POST `/api/export` | 对 saved_id、方案、冻结输入、源文件逐项校验；直接调用接口同样受保护，不靠页面按钮权限 |
| GET `/sources/...` | 只允许明确授权来源；个人文件受本人规则保护，不能凭文件名或路径下载；公开白名单不包含学生样本 |
| GET `/api/health` 与静态资源 | 明确公开最小信息；不返回学生、方案、学业、秘密配置或完整版本输入 |

没有有效会话时，敏感接口返回未认证状态；已认证但对象不属于本人或不存在时采用一致的不可访问响应，不透露他人是否有该档案/方案。失败不产生读取、修改或导出副作用；审计中保留内部原因。具体错误码、速率限制与登录失败防枚举行为在实现时统一验收。

## 8. 检索、RAG、缓存与原文件隔离

本节只规定安全边界，不设计检索算法、索引接口、真实数据源或用户 UI。

- 个人数据检索在取回材料前使用服务端本人范围过滤，不能先检索全体学生，再要求模型忽略他人内容。引用、上下文、摘要和生成答案都继承相同范围。
- RAG 的个人材料及其分块、向量、元数据必须保留 owner_student_id、security_realm 和来源权限。公共知识与个人资料可分别索引；共享索引也必须有强制过滤，不能靠提示词实现隔离。
- 缓存键至少包含安全域、本人键、相关输入版本和授权策略版本。公共计算缓存只有在输入及输出确实不含个人数据时才可共享；绑定撤销或权限改变后不能继续返回旧授权缓存。
- Agent 工具、后台任务和异步计算使用服务端固定的本人上下文，不能因用户话术或模型参数切换学号。任务完成取回与下载时也重新验证访问权。
- 导出文件、原始 Excel/截图、快照、来源定位和临时文件与主体隔离。访问原文件需与 API 一致授权；下载标识不可代替权限；不能在公共静态目录暴露个人材料。
- 日志、错误、调试输出和审计只保留必要信息。认证返回敏感材料及学校凭据不写入 Git、SQLite 业务 JSON、资料引用、模型上下文或导出。
