## 2. 具体工作和验收产物

1. **冻结最终范围与账本。** 保存本轮截止时间、运行/映射版本、主要范围清单和终止证据、取消/未请求/失败/未知分别列项。核对最新3165次预留尝试与成功、空响应、失败、未确认尝试的关系；不能把工具中断视为HTTP成功。历史原件和回执不覆盖，新增最终清单。
2. **完成内部完整性审计。** 使用现有离线校验器核对对象哈希、课程父观察→本次目标→班次响应绑定、去重/冲突、PDF目录→文件→页数/文本对应。已通过且输入/代码未变的检查引用原证据，不无理由重复。对之前source保留首课模板的问题，解释模板来源和实际bound target，追加派生说明；不重写原回执，不导出Cookie/请求头。
3. **交付字段可用性报告。** 按课程、班次、时段、考试、容量和个人页面状态分别统计已观察/未知/冲突/不可适用及缺失数量，区分“解析不了”和“来源未提供”。精确周次、校历、待定考试、先修完整细则、稳定班身份和正式中选/获分继续按证据标记；不把已选变成中选、把目录选项变成课程。列出哪些字段可供下一步结构化适配、哪些会阻止确定性课表计算。
4. **整理培养文档交付索引。** 保留教学计划号、适用年级/专业的来源观察、PDF哈希、页定位全文、解析版本与提取问题，能够从文档索引回到原件/页码。图示、条款语义、现行版本、适用本人和规则审核未完成单列；不把162份解析成功写成RAG检索或政策审核完成。此步骤整理现有产物，不做全量语义标注或向量化。
5. **形成最终本机交付说明。** 说明原始层/规范化候选层/索引/失败及unknown清单的入口、数量口径、可复查方式、用户排除范围、来源字段缺口及应用接入前置条件。原件、真实定位、个人状态和审计日志留Git忽略目录；公共开发进度只记去敏数量、证据编号和验收边界。无提交/推送/部署。
