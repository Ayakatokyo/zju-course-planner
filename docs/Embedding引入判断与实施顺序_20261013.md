# Embedding 引入判断与实施顺序

日期：2026-10-13。状态：分析建议，附当前关键词检索探针。没有安装、下载或调用 embedding/生成模型，也没有修改应用检索实现。

## 1. 判断

可以开始引入预训练 embedding 模型，先以已有非个人参考语料做本机对照实验。54 个块足以验证编码、检索、版本、过滤和引用链路；不需要等待学校认证或真实个人数据接入。它们不足以训练领域模型或证明面向真实学生的检索质量，本轮也不建议微调。

Embedding 把查询与依据文本转换为可比较的向量，目标是让不同措辞但含义相关的问题找到依据。它不执行学分/时间计算、不审核候选规则、不补充不存在的教学班，也不使 Agent 页面自动理解需求。生成模型的理解/澄清/工具调用应作为另一条可并行推进的开发线。

## 2. 当前实际基础与缺口

核对当前代码、README、进度、实验目录及未提交变更：应用仍为0.2.0，HEAD为8be3e83，数据接入设计/参考检索以及10月10日LLM解释准备仍在本地工作区；未覆盖或清理这些已有变更。

现有检索从原交接JSON生成54块：19课程、23待审核候选、12来源问题。标题加正文共4,885字符，中位64、最长439字符，尚未包含三份培养方案PDF全文。已有稳定语料版本、来源摘要、JSON pointer和PDF证据页集合，适合固定输入做算法对照。原23候选仍不可执行。

现有8题主要是课程码或接近原文的短词，检查目标记录是否在前5条，并不衡量无关项、排序或无依据问题。历史8/8不能证明embedding已经必要、有效，或当前检索能理解自然语言。

本轮实际运行7个探索查询，保存于[探针记录](../validation/embedding_readiness_20261013_probes.json)，不是正式准确率评估：

| 查询与范围 | 当前实际结果 | 对下一步的意义 |
| --- | --- | --- |
| 材料：Python | 返回Python课程及计算机任选规则 | 精确名称已有良好基线，应保留 |
| 材料：想学写脚本处理数据，应该从哪门课开始 | 返回计算机任选规则，同时混入学分归属和大学写作；没有直接返回Python课程记录 | 需要测口语表达、语义相关性和噪声；任选规则内仍有Python引用，不能描述为完全没有相关证据 |
| 材料：会写程序但不想上C语言，还有别的选择吗 | 前列仍有C语言课程及近名诊断，Python课程靠后 | 否定/约束理解不能只靠向量相似度，需要澄清和工具校验 |
| 商务：学校有没有关于停课、补考和缓考的规定 | 返回ok，命中第四课堂和劳动教育 | 词重合不保证证据相关；向量近邻也会返回无关项，需要无依据识别 |

这些结果证明当前词法基线存在值得测量的缺口；没有实际embedding结果，不能承诺它会改善上述每一种问题。课程名与培养行也不能替代课程大纲，对课程内容/能力培养的回答必须受现有证据限制。

## 4. 模型与最小技术方案

首个候选建议 **Qwen/Qwen3-Embedding-0.6B 本地推理**。官方模型卡标明0.6B、多语言、最高1024维，并提供Sentence Transformers与Transformers用法；查询侧使用检索任务提示，文档侧不添加相同查询提示。Apache-2.0是模型许可，不是学校材料的使用许可。[官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)、[官方仓库](https://github.com/QwenLM/Qwen3-Embedding)。

本机只读检查为Apple M5、24 GiB内存，当前Python为3.13.13。从模型规模和本轮短文本量判断，小模型本地实验具有合理可行性；尚未实测运行时兼容、内存或耗时。依赖放独立实验环境，先确认CPU/本机加速路径，不能原样照搬CUDA示例。模型并未安装或下载。

如后续需要模型对照，可选 **BAAI/bge-m3**；官方模型卡支持多语言和多种检索表示。第一轮只测dense即可，不必同时接入它的sparse/multi-vector功能。[官方模型卡](https://huggingface.co/BAAI/bge-m3)。这只是候选，不是本项目测得的优胜模型。

54块无需独立向量数据库：元数据保留在现有文件/SQLite方案中，向量用本地矩阵保存；先筛选允许的记录，再在该集合做精确余弦相似度。仅54×1024个float32数值约216 KiB，不含模型权重和元数据。首版无需近似索引、重排模型或新Agent框架。

向量版本至少固定：源/文本摘要、chunk与文本构造版本、模型名称与实际revision、tokenizer/pooling、query提示、维度、归一化、精度/量化及推理依赖版本。查询与文档必须使用同一可兼容配置；换模型/维度需要重建，不能混用旧向量。权限和审核字段留在过滤逻辑中，不靠把owner或pending字样拼进embedding文本实现。

## 5. 建议执行顺序与验收

1. **固定语料和问题集。** 先保持当前54块，审阅每块标题、原文和diagnostic角色。人工标注约40题，覆盖代码/名称、口语同义、否定与多条件、专业/路径/争议、无依据/范围未知。记录相关证据和预期unknown；建议24题开发、16题保留，按问题意图分组，避免同义改写同时落入开发与保留集。
2. **做三组同条件对照。** 当前词法、单独向量、词法+向量混合使用相同语料、范围和问题。精确代码可直查，其他结果可按排名融合；不要直接相加两种不可比的原始分数。先比较，后决定默认策略。
3. **检查收益与退化。** 看Recall@5、首个相关结果位置、前列无关项、无依据误命中和引用支持。范围错误、候选误启用、伪造出处不得发生。向量一定能找出“最近的文本”，不代表存在答案；无依据阈值/判定策略只在开发集校准，不能先编一个通用0.8阈值。
4. **扩展PDF覆盖。** 有了同语料的基线后，另立语料版本提取培养PDF。按条款/表行、标题/例外与跨页上下文分块；不以模型最大上下文作为chunk目标。新增全文后重做问题标注和对照，分清收益来自语料增加还是检索变化。
5. **接受限检索工具与生成模型。** 先在synthetic主体上验证auth/grant/适用绑定、引用回查和撤销，再把检索交给Agent。模型解释真实工具结果；生成或调整课表仍继承锁定、固定项和版本并重新计算。

与此同时，利用已有[LLM解释输入实验](../experiments/llm_explanation/README.md)选定生成服务并取得一次真实模型回复，核对解释与计算证据；随后逐步加入需求提取、澄清和受限工具调用。Embedding实验不应成为继续保留禁用对话入口的无限前置条件；生成模型最小synthetic闭环也不要求先有向量检索。

本轮只完成准备度判断、探针和实施建议。未重跑完整146项回归；该数量仍指历史记录。未调用模型/学校系统，未作页面或真实业务验收，未提交、推送或部署。原八项与权限未覆盖项维持原状态。
