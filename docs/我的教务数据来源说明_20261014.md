## 1. 数据经过哪些环节

学校统一认证验证凭据 → 建立学校教务临时会话 → 查询已认证本人资料 → 本机服务建立本人授权绑定 → 固定学校业务接口 → 允许字段投影 → 分页/覆盖检查 → 原值及规范化解析 → 本机界面展示。

真实学校数据经 `school_client/personal_school_client`，不使用模拟学生A/B。学校认证/菜单的 HTML 不能作为个人业务 JSON 混入解析；普通业务只保留允许字段，原始未知字段不会自动进入界面。原响应中的个人业务值仅在本机处理，私有投影及 PDF 保存在 Git 忽略的本人目录；没有进入共享 RAG、原 inputs、模型或 Embedding。

- 业务接口与投影：[school_http.py](../course_assistant/school_http.py)，`DATA_ROUTES`、`_business`（43–50、854–935行）。
- 本人授权、私有来源版本和解析编排：[school_accounts.py](../course_assistant/school_accounts.py)，`_connection`、`_authorize`、`_capture`、`fetch`（141–159、323–345、390–438行）。
- 分页、代次和缓存：[student_source_client.py](../course_assistant/student_source_client.py)，`_validate`、`fetch`（215–317、329–416行）。
- 允许字段与状态：[student_source_parsers.py](../course_assistant/student_source_parsers.py)，`PROFILE_FIELDS`、`ACADEMIC_FIELDS`、`TIMETABLE_FIELDS`、`MEETING_FIELDS`、`EXAM_FIELDS`（22–112行）；[student_sources.py](../course_assistant/student_sources.py)，`sanitize_payload`（80–117行）。
