# 浙江大学选课助手开发进度

最近更新：2026-10-09。本文是本项目后续开发进度的统一记录入口。

## 1. 当前状态与最新约束

**当前阶段：字段与登录权限设计已保存，正在完成新对话交接及 Git/GitHub 仓库建立；本轮业务代码继续暂停，新的对话再恢复开发。**

- 已保留此前 P0/P1、本地服务、存储、导出和前端的代码草稿。存在代码不等于模块已完成，当前没有完成整合验收或交付可运行产品。
- 用户提供的 Excel 用于了解学生档案、培养审核和学业认定的字段、结构及状态。它是开发参考样本，不能据此确定真实使用者必须上传 Excel 的产品流程。
- 用户最新确认的使用方向：**学校身份登录 → 可信本人学生绑定 → 本人档案检索 → 输入偏好 → 针对性检索 → 给出答案或方案。** 姓名、学号等输入只在本人范围内匹配与校验，不能授权查询他人。
- 字段字典已保存，尚未迁移至代码。最新授权：补齐登录权限设计、总结当前对话形成开发交接，建立本地 Git 仓库并创建关联 GitHub 仓库；后续新对话进入代码开发。
- 已保存 `docs/登录认证与权限设计_v1.md`：学校认证接入待确认，不存学校密码；服务端身份限定本人资源，mock 仅 synthetic、不在认证失败后降级。认证、会话和授权仍未实现。档案来源与检索接口尚未设计，不能假定已有检索能力。
- 暂未通过学校 OpenAPI 取得所需数据。未来档案与课程检索的实际来源和接入方式仍待后续讨论；这不是本轮要求用户补交资料的清单。
- 首版业务范围保留为选课规划、比较、调整、保存与导出。RAG 提供依据检索，Agent 组织对话与工具调用，确定性程序负责计算。
- 原交接资料保持只读；原 23 条规则候选不得直接启用为官方规则。模拟规则、学生、教学班和校历独立保存并标注 synthetic。

## 2. 状态定义与维护方式

| 状态 | 含义 |
| --- | --- |
| 已完成资料工作 | 已读取、整理或保存对应文档；不表示软件功能完成 |
| 代码草稿 | 已写入代码，但仍有集成、语义或验收工作 |
| 历史局部验证 | 之前对当时版本做过局部检查；不能代替当前版本的整体验收 |
| 未完成验收 | 尚未取得完整验收证据，不能标为已交付 |
| 未开始 | 尚未实现该项能力 |
| 暂停 | 依用户要求停止该类工作，未经后续指示不恢复 |

后续每轮实际开发或验证结束时，更新当前状态、任务矩阵、问题清单及验收状态，并在末尾追加变更记录。记录具体文件、验证范围和结果；没有运行的测试写“未运行”，历史结果标明历史属性。设计文档负责设计内容，本文件负责进度，避免多份文档分别宣称完成度。
