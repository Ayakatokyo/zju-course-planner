## 本次讨论明确的架构

保留“原问题 → 模型理解并直接选择受控工具 → Harness执行 → 工具结果回到同一上下文 → 模型回答”的单循环。不是先固定分类、全量取数后才允许模型工作，也不增加第二个评审Agent。

1. 服务端认证确定账号和本人范围；登录建立连接、提供基础能力，不代表所有业务数据都已获取。
2. 每轮先做本机context预检，模型收到原问题、必要近期历史、当前任务和可用工具。
3. 模型选择查询、培养检索或方案工具；Harness负责参数、本人权限、必要来源依赖及版本检查。
4. 成绩/课表/考试使用结构化查询；培养PDF使用原文检索；课程参考和获准历史教学班使用各自受控检索；方案由确定性计算生成。
5. 工具结果携带有界事实、缺项、来源和必要上下文，按tool_call_id回到模型；模型可继续取证或通过finish_answer交付。

**前置工具语义检索只是未来可旁路辅助设计，目前未启用。** 当前优化重点是工具内部的检索质量和返回上下文。独立Cross-Encoder、登录后台全量预热同样未实施。模型和RAG不替代权限、课程等价认定或确定性求解。

详细架构及图见[职责收敛后的项目架构](项目架构_职责收敛后_20261021.md)。

## 下一轮适合继续优化的内容

1. **优先观察实际普通问题。** 从用户真实不满意的回答出发，定位工具输入、返回事实和最终正文；不要重新跑无限矩阵或重建整个架构。
2. **解释措辞仍可收紧。** “更分散”“每日负担更均衡”“少跑”等是模型定性概括，不是完整个人课表或正式排序结论。需要时用现有节次事实解释，避免扩大到个人实际安排；无需增加评审模型。
3. **偶发格式修复仍存在。** 最终三轮有1次自动恢复，未阻断交付；如继续影响等待时间，再按真实失败定位协议问题。
4. **旧培养与新课程对应暂缓。** 原course_search_required受阻结果保留；临时增加的恢复提示及对应测试在v41启用前撤回。不得把“暂缓”改写成“已解决”。

正式培养适用、课程等价/认定、最新可选性、本人课表/考试完整冲突及完整语义仍未验收；只允许已获准的2026-2027-AW历史课程条件测试，不扩学年、端点或选退课。
