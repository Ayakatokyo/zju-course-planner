# 数据接入契约与最小切片 v1

日期：2026-10-09。状态：可审核设计，附本机只读参考资料切片；学校认证、真实个人数据连接和模型均未接入。应用仍为 0.2.0。本文补充字段字典，不改原 inputs，不把设计对象等同于已建数据库。

## 1. 本轮核对与决定

先读 README、AGENTS、最新交接、进度、权限、字段、模块与 Agent 设计，再按交接顺序核对原输入及代码。开工 Git 干净，`main@8be3e834f5f1968a0134e079dd0b225be692f48f` 与实际 `git ls-remote` 的远端 main 一致。重新执行的 133 项基线全部通过，清单 17 项及 ZIP 七文件一致。证据见 [基线摘要](../validation/data_rag_baseline_20261009_validation.json)。本轮没有重新逐页审阅 PDF、读取私有 Excel/截图或访问学校登录后的页面。

核心仍是对话获得推荐课表；表单辅助核对。本轮不接模型，不启用发送按钮，手动 synthetic 预览不能称为 Agent 理解。先拆开认证、本人数据获取、依据检索三个契约，再以可复核的交接 JSON 验证最小检索切片。

## 2. 可取得的数据与许可盘点

“可取得”分别指已经在本机核验、只有字段参考、可申请但尚未授权、未知。以下许可描述是本项目的使用边界，不能由持有文件、公开页面或私有仓库推导批量采集、再发布或外传许可。

| 来源域 | 当前证据与覆盖 | 许可 / 本人绑定 | 接入选择与待确认事项 |
| --- | --- | --- | --- |
| 学校认证 | 本轮只读核验官方服务页，存在应用接入申请流程 | 本项目获准应用、负责人、环境、回调与主体属性均未确认 | 获准后根据提供材料选择适配协议；不预设 CAS/OIDC/SAML/OpenAPI，不收学校密码 |
| 可信本人绑定 | 本机固定 A/B synthetic；没有学校验证主体 | `principal → provider subject → verified binding → internal student`；学号输入不能创建绑定 | 核验学校是否返回可信学生属性或允许的独立映射；缺失/多义/撤销时拒绝个人访问 |
| 档案与个人要求 | Excel 字段设计记录，非运行来源 | 样本只作参考，不能通过 mock 查询原件 | 学校获准数据接口、学校提供的本人交换渠道或获准本人页面读取均仅为待核验路径；字段/频率/绑定证据未知 |
| 修读 / 成绩 | 已有字段与状态分析，无运行时本人账本 | 数据源许可独立于登录；需要本人范围与用途 | 学校尝试 ID、修读学期、重复政策、成绩量表及观察时间未齐；不将 Excel 行视为稳定修读实例 |
| 认定 / 替换 / 学校审核报告 | 字段参考，部分语义未知 | 仅本人及适用要求范围 | 原报告与项目计算分开；认定渠道、替换双方和正式政策待确认 |
| 志愿 / 页面已选 / 正式中选 | 两张截图的历史字段分析；无当前正式结果接口 | 截图可能含本人信息，保持 restricted_reference | 选课阶段、状态映射、班号、完整可见范围与正式结果依据待确认，不由按钮/颜色推断正式成员 |
| 当期开课 / 考试 / 余量 | 原模板 0 条；截图局部七行的设计记录 | 是否可共享与何种采集许可未确认 | 班号、周次、分页、观察时间、资格与联选待确认；余量为瞬时观察，负数/零/未知分别保留 |
| 校历 / 节次 | 现有运行数据仅独立 synthetic | 真实校历未取得与核验 | 学年、学季、校区、节次表与日期映射要有独立版本，不能套合成校历 |
| 培养依据 | 原本机 3 份 2026 级方案、19 课程、23 候选、12 问题及来源哈希 | 当前授权用于本机开发与审阅；不等于官方现行、个人适用或公开发布许可 | JSON 可先作参考证据；PDF 全文提取/分块另需核对；候选不得进入执行规则集 |
| 官方通知 / 手册 | 原索引有历史网页指针，非当前快照 | 公开可读不推导所有后续用途 | 真正入库时重新取得文本、版本、适用对象与保存/索引使用条件；本轮不自动抓取 |
| 本人偏好 / 对话 | 已有 synthetic 条件；没有模型会话持久化 | 服务端本人 owner/realm；外传许可另定 | 用户需求可成为偏好依据，不能成为成绩、正式中选或学校身份依据 |
| 模型服务 | 无配置或选型 | 本地/外部 API 都需明确调用范围；个人数据外传单独授权 | 地址、协议、模型能力、预算、超时、数据处理与资源条件未确认；本轮不索取 Key、不调用服务 |

本轮核验的[浙江大学统一身份认证服务页](https://its.zju.edu.cn/tysfrzwgr/list.htm)列出单位应用申请、材料准备及开发者平台提交流程。它支持“存在申请路线”，不能证明学生个人项目已获准，也不证明存在本人学业接口。本轮未提交申请、联系人员或登录学校系统。

私有字段参考的存在依据为已有字段字典及交接记录；没有重新取得可复核原件，不将历史样本当当前页面验收。Excel/截图不规定用户上传，也不指定为未来产品入口。

## 3. 认证接入与本人来源分开设计

| 契约 | 可信输入 / 输出 | 正常路径 | 拒绝与未知路径 |
| --- | --- | --- | --- |
| Auth adapter | 服务端登记的获准应用配置；经协议验证的认证结果 → VerifiedPrincipal | 验证签发来源、受众、时效、请求关联、重放等最终协议要求，轮换会话 | 未配置、认证失败、超时、伪造、重放不得产生学校主体，不降级 mock |
| Identity resolver | 已验证主体与可信映射证据 → StudentIdentityBinding | 一个有效本人映射，记录证据与绑定版本 | 待绑定/冲突/撤销/不匹配时可显示状态，不能取得个人材料 |
| Source grant | 主体、学生、来源与获准用途 → PersonalDataSourceGrant | 明确允许 read/normalize/compute 或 retrieve；记录到期与撤销版本 | 认证成功不创建授权；未经许可不请求来源、不建个人索引 |
| Personal adapter | 服务端本人上下文、有效 grant、覆盖请求 → AcquisitionEnvelope | 只读取得本人数据，核验来源绑定，剥离凭据后交给 S0 | 客户端/模型不可指定学号切换对象；来源返回他人数据整体隔离，不“修正 owner” |

未来个人源适配器在代码结构上可分别实现 `profile`、`academic`、`recognition`、`selection`，不能以一个登录 Cookie 当作全域读取许可。请求学号如为学校协议所需，只能由可信服务端映射生成，不开放任意学号参数。

认证与数据通道保存不同配置和证据。认证票据、学校会话与秘密配置不进入业务 JSON、chunk、日志、导出或模型；上游必要的连接凭据在获准方案下由专门连接层保护，项目不建立学校密码验证功能。

## 4. 原始观察到规范化数据的契约

拟议 `AcquisitionEnvelope` 是连接层生成的逻辑对象，不是学校 API Schema、客户端导入格式或已实现接口。

| 字段组 | 必需语义 |
| --- | --- |
| 归属与许可 | `source_id/source_kind/data_kind/data_scope/security_realm/owner_student_id/grant_id/grant_version/purpose`；个人 owner 由服务端注入，上游本人标识另核验，不能信任原件中的 owner 声明 |
| 原始身份 | `raw_digest`（实际已剥离凭据的材料字节 SHA256）、`upstream_revision`（未知可 null）、`raw_reference`（受保护的不透明引用）；不把真实本机定位写入共享设计或响应 |
| 时间 | `observed_at`、`recorded_at`、`valid_from/valid_until` 分开；不知道观察时间保留 null；项目登记时间不补观察时间 |
| 覆盖 | 学年/学期、入口/过滤条件、课程展开、分页与加载范围、完整性、可见记录数、裁切；`complete_within_scope` 只对显式范围成立 |
| 变更方式 | `append_observations/replace_within_scope/delta`；默认 append；完整范围替换需要同范围证据与预期活动版本；delta 需要来源稳定键和可信序列 |
| 处理版本 | schema/parser/mapping/resolution 版本、字段级来源与状态、问题列表、记录身份解决状态 |

三层：受保护原始观察不可变；规范化记录以来源和映射版本生成，保留 EvidenceRef；计算结果单独冻结全部输入版本。原始层只保留业务证据及必要上下文，不保存密码/票据/完整登录页。对于目前已有个人样本，原件仍在 private 或外部目录，不转为可访问的运行来源。

字段采用字典六态 `known/unknown/not_provided/not_applicable/pending_verification/conflicting`；计算仍汇总 pass/fail/unknown。明确已知空集合用 []，未知集合用 null。已知 0 和 false 保留；学分用 Decimal/十进制文本，布尔值不作为数字。

| 原字段 / 原观察 | 规范化落点 | 不允许的推断 |
| --- | --- | --- |
| 本人身份表头 | Profile 观察 + 身份核验差异 | 不能创建登录权限，不能由学号猜入学年 |
| 要求标题/审核阈值 | 个人 RequirementNode + SchoolAuditReport | 不覆盖通用方案，不把报告视为项目复算 |
| 成绩行、课程代码、学分、通过文字 | AcademicObservation；经证据解决后 Attempt | 同代码不合并实例；学分额定值不等于已获分；被替代行不产生修读事实 |
| 美育、活动、替换文字 | Recognition/Substitution/Allocation 各自记录 | 个人替换不升级全校互认；条件覆盖不重复加实际学分 |
| 课程代码与括号代码 | CourseDefinition + CodeLink 观察 | 同名不合并；括号代码不命名为班号 |
| 教师与班行 | 快照内 Section + source_section_id 可空 | 无稳定学校班号不跨快照自动合并 |
| 星期、节次、秋冬 | Meeting 观察；周次/校历可空 | 秋冬不自动映射全周；缺时段不当空闲 |
| 考试时刻 | ExamArrangement | 不混入上课 Meeting；时区未知不自动转 UTC |
| 余量/容量/待定 | CapacityObservation | 负余量、已知零、未知分别保存，不推算保证中选 |
| 页面已选、志愿、正式课表 | EnrollmentObservation/WishItem/正式来源成员 | 页面“已选”不推班号或正式成员；正式中选不推已获分 |

## 5. 幂等、冲突与更新

拟议幂等键：`(realm, owner或shared域, source_id, coverage_digest, upstream_revision或raw_digest, parser_version, mapping_version)`。同键同内容返回原 batch/snapshot，不重复添加学业事实；同上游 revision 不同 raw_digest 是完整性冲突。相同内容但不同范围、owner、grant、映射或观察时间不能任意共用回执。缺稳定班号/修读 ID 的行只在原观察内稳定，跨快照匹配产生待核验链接，不能用课程号、教师+时段或成绩值自动去重。

`raw_observation_id` 可由来源、材料摘要、定位生成；`normalized_record_version` 再包含 schema/mapping/resolution 版本。内部稳定键不冒充学校 ID。新解析版本并存，审核决定活动投影；重跑映射不创建第二份已获学分。

冲突按字段与上下文保存 SourceAssertion。不同用途的分类保留差异；同范围同属性相互矛盾时 active value 置 unknown/conflicting。学校明确修订在适用范围内取代旧版本仍保留旧证据；没有效力/优先级依据时不采用“最后写入胜出”。认定、课程身份、官方效力及规则执行审核是不同决定。

更新事务顺序：

1. 再验证会话、绑定、grant；固定本轮预期输入版本。
2. 原始观察与覆盖证据入隔离暂存，检查本人标识、结构、凭据和完整性。
3. 规范化与差异预览；缺字段保留，冲突不发布唯一事实；批次失败不改活动数据。
4. 发布前再验证权限和预期版本，用事务原子写新快照、来源/问题引用和活动指针。重复重试取原回执；版本竞争返回 stale_input，不强行覆盖。
5. 旧方案保持冻结；当前方案标需重校验。继承当前锁定、固定项、预置/正式成员和偏好版本后调用现有确定性校验。班次消失报待确认，不删除锁。
6. 使相关索引/缓存版本失效；权限撤销时停止新读取、引用与缓存返回。合法留存/删除期限待来源许可确定，保留最小非内容撤销审计；备份同样受策略约束。

部分页面和范围未知不能因“没再看到”删除原记录；完整同范围替换仍只生成新版，不能擦除修读历史。delta 中删除表示有依据的撤回观察，不代表未曾修读或未获学分。

## 6. 最小接入切片与阶段门槛

本轮切片：已有交接 JSON → 校验原清单 → 规范化参考 chunk → 强制方案/语料版本过滤 → 本机关键词候选及可回查引用。课程、候选与问题共 54 条参考记录；只取现有 JSON 文本，不重新 OCR、PDF 提取或联网采集。规则表达式不进入执行器，所有候选保持 pending。没有个人原文件或索引，不通过 mock 接真实材料。

代码 [reference_retrieval.py](../course_assistant/reference_retrieval.py) 与 [测试](../tests/test_reference_retrieval.py)为离线设计验证；不挂 HTTP、不改变工作区、不调用模型、不缓存。显式 `plan_id` 是开发者选择的“参考资料范围”，不是学生权限或可信方案绑定。运行时接入必须用 AuthContext + grant + StudentPlanBinding 生成范围，不能直接开放本切片函数为模型工具。

本切片的幂等只证明同一已校验资料/映射产生相同 chunk 与 corpus ID；持久化 batch 事务、跨源修读去重和更新发布尚未实现。原 JSON 不是完整文档，未命中只说明这一参考范围未命中。

| 后续阶段 | 可独立推进 | 启用条件与验收 |
| --- | --- | --- |
| T1 synthetic 个人源 | 构造原观察→规范化→受限事实工具的隔离夹具 | 本人 auth/grant、A/B、撤销、幂等、冲突、版本竞争与 unknown；不以替身证明学校获取 |
| T2 synthetic Agent | 模型适配/受限工具/多轮状态，先用替身测协议 | 用户选定并授权本地或外部服务后验证真实模型；每轮锁定/版本继承和实际工具证据 |
| T3 获准依据 RAG | PDF/政策块及审核状态、引用、语料评估 | 文本可复核、用途许可、现行与适用状态明确；权限/范围在评分和正文加载前执行 |
| T4 学校认证与个人源 | 认证与数据适配器分别交付 | 获准应用/协议/可信映射；来源许可与本人绑定样本；生产会话和相关 A 项验收 |
| T5 真实页面 | 只读适配获准、可复核页面样本 | 字段、状态、分页/加载、时间、班号、周次与覆盖人工对照；不自动选课 |

下一最小个人源建议先选“本人档案+适用绑定观察”，而非直接完整成绩/选课抓取：先证明身份与来源绑定、unknown 和更新，再拓展 Attempt/Recognition/Selection。但取得哪一种真实来源先由实际许可与可复核样本决定，不把此建议当学校既有能力。

未确认依赖：学校应用主体/协议/环境；可信学生映射；各本人来源用途/字段/更新与保存条件；适用方案与规则审核；模型服务及传输授权。本轮不等待这些依赖才保存可审核设计，也不擅自替用户完成申请或模型选型。
