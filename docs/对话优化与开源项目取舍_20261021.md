# 教务助手对话优化与开源项目取舍

目标是完成常用的“查询→理解结果→追问”和“提出课程需求→生成组合→连续调整”旅程。当前主要缺口在上下文与回答契约，不在学校登录或数据库。已有只读来源工具、确定性计算、本人授权和 SQLite 会话保存继续使用。

## GitHub 项目如何用于本项目

以下按 2026-10-21 的官方仓库、文档核对；本轮未安装框架或复制其源码。

| 项目 | 可借鉴的成熟做法 | 本项目采用方式 |
| --- | --- | --- |
| [PydanticAI](https://github.com/pydantic/pydantic-ai) | [消息历史](https://github.com/pydantic/pydantic-ai/blob/main/docs/message-history.md)可承接连续问答；[输出校验](https://pydantic.dev/docs/ai/core-concepts/output/#output-validators)允许有预算的结果重试 | 最适合将来替换 Python 中模型循环的一层。本轮先补近期问答和一次任务纠正，仍由现有代码核对来源、数值、身份与工具。不能将符合 JSON 格式等同于完成用户任务。 |
| [LangGraph](https://github.com/langchain-ai/langgraph) | [会话记忆](https://docs.langchain.com/oss/python/langgraph/add-memory)把消息和状态绑定到线程，通过 checkpoint 保存 | 借鉴“会话语境与当前执行状态分开”的做法。现有 SQLite 已存轮次、待澄清任务、方案及运行记录；目前无需再引入一套状态图和持久化系统。若将来出现多步骤中断恢复、人工审核或后台长任务，再评估迁移。 |
| [Celechron](https://github.com/Celechron/Celechron) | 面向浙大学生的应用，可作教务数据组织和学生使用路径的参考 | 保留当前已验证的本人登录与取数。已有接入文档记录过其源码参考；本轮没有接入新接口、扩采或复制实现。它不能直接解决 Agent 多轮追问。 |

优先顺序：先验证现有工具能被模型正确连续使用；若还需压缩自维护循环，再用 PydanticAI 做同一工具契约下的独立适配验证。不能为了“用了框架”同时改认证、存储、来源投影和推荐计算，否则会增加排查成本。框架本身不能证明答案有依据，也不能判断学校培养规则是否适用。

## v24 本轮具体改动

1. 实时来源会话发送最近六轮以内的用户问题与已展示答复，限制总量；不携带原始工具包、供应商推理或旧工具引用。它们明确标为历史语境。本人/连接归属和出站策略检查仍在服务端；更换模型等原有重置边界保留。最新个人数据仍须本轮取数。
2. 增加 `lookup_academic_terms`，提供成绩未知、均值与绩点、完成状态、学分、来源范围、读取覆盖、培养适用、方案条件八类系统字段说明。模型选择相关主题后自然表述，引用显示为系统说明；该工具不读取学校数据，也不承担学校政策或本人认定。
3. 明确逐学期请求不能用主修总览替代。该常用表达下，未明确学期的查询会在学校调用前停止并要求澄清；解释追问误选能力介绍时最多纠正一次，重复偏题按失败处理。
4. 调整回答提示：中文学期、先回答当前问题、概念解释通常一至两段；成绩概况分行展示。概况和已有计算摘要直接提供绑定当前引用的合法结论结构，减少模型猜输出格式。已实际计算后，候选检索结论不再提示继续生成。统计仍由服务端聚合，推荐保护与求解保持原有路径。
5. 普通模式隐藏空的供应商推理列，保留真实处理记录与模式信息；开启思考但未返回文本单独说明。未知模式不能在保存模型选择时被隐式写成关闭。已明确关闭仍有效，历史推理不会补造。

## 验证与剩余工作

工程、真实模型配合合成数据、实际页面和学校本人验收分别记录在开发进度第83节及相应 validation 回执。真实 Flash 的概念追问已取得有限支持；前期探索出现额外展开未问字段、重复读取已有计算，最后的限定旅程已收窄。它不证明任意问法都能保持最少调用或最简答复。

本轮的纠正门槛只覆盖已复现的常用错误，不是通用语义评审器。新字段说明也不是完整教务知识库。真实本人多轮、培养适用、正式开课/资格和推荐业务验收仍需独立进行；合成数据中的实际模型调用不等于学校业务验收。

用户明确确认后，18875已启用v24，页面及脚本返回已核对。原学校登录因重启结束，用户选择自行重新登录；原数据库记录数量保留。新版本人真实旅程尚未执行，见启用回执。
