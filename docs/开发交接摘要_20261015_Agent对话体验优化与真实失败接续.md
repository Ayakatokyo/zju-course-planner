## 4. 当前真实运行链路与能力边界

```text
页面提交 /api/chat/turn
  → 服务端验证本人、会话/连接/HTTP代次及资料/模型版本
  → personal_acquisition 按问题准备缺少的成绩/培养来源
  → personal_dialogue 服务预检 get_my_context
  → DeepSeek 选择受限工具 → 本机执行 → 白名单证据投影回模型
  → 模型返回结构化决定 → 格式/引用/部分能力限制检查
  → 保存当轮结果、模型协议历史与私有运行记录

并行：页面 /api/chat/progress 轮询实际阶段及SSE可见推理
结束：/api/chat/run 补齐运行详情；历史过程按需载入
```

当前个人模型只有三个声明工具：`get_my_context`、`query_my_records`、`search_my_curriculum`。读取学校成绩/培养来源由服务准备阶段发起，不是模型自由选择的通用工具。来源准备目前依赖中文关键词及明确学年/季节匹配；泛问成绩准备主修ALL-HISTORY，指定学年和秋冬/春夏准备学期成绩，培养相关问题准备本人文件。已有对应来源复用，未指定的课表/考试学期不自动猜测。

记录查询为已读快照内筛选；培养检索为私有PDF物理页/段落及精确代码/词法检索，尚非Embedding。学校读取有分页预算，已读部分不等于完整历史；模型记录出站还有字段/字符预算，不能用前15条展示代表完整来源。成绩概况在选定快照全部匹配行上计算纯数字0—100的简单非加权均值、范围及数字/非数字/未知数量，独立引用，不能声称正式GPA、绩点或已获学分。

模型最终输出受限JSON：answer须本轮证据引用；clarify/not_ready使用受控结构；general_chat只有有限身份/问候/能力/澄清意图，由服务呈现对应说明并标记来源。这是当前实现事实，是否过度约束正常交流、导致合理问题被拒绝，应结合真实样例检查；不得直接删除授权或事实依据约束换取表面流畅。

**当前不是可以任意运行终端命令或Python脚本的通用编码Agent。** 执行的是受控服务函数和领域工具，因此没有某脚本执行记录时，不能补造“运行脚本”步骤。若下一轮认为需要脚本/计算工具，应明确用途、允许输入、本人权限、隔离和执行回执，再决定是否实现。

供应商可见推理不等于完整内部思维，也不是脚本执行证据或答案正确性的证明。可见推理当前每事件最多4096字符、每run最多16384字符；实时缓存256请求、900秒，末96字符缓冲用于分片脱敏。短推理可能到模型返回才显示；历史须按需载入；这些实现细节可能影响体验，需实测而非直接认定为最新根因。诊断故障不应触发重新发送同一个模型请求。

## 7. 下一轮建议执行顺序与验收

1. **保留当前登录和运行现场，先复现。** 先核对实际端口/进程、静态JS/CSS及加载代码、当轮模型/开关。取得一条最新失败提问、期望依据和实际结果；必要时再请用户提供最小文本样例或在页面登录，不索取密码、Cookie或密钥到聊天。按request_id/run_id串起当前调用。
2. **定位真实断点。** 按本人范围/来源准备→实际查询参数与覆盖→检索命中及投影→模型工具选择及协议→最终验证/拒绝→页面答案逐段检查；另行检查SSE字段→有界进度→HTTP轮询→前端过程区。不要在未定位前只加prompt、扩大正则或猜测模型能力。
3. **形成整体体验的具体调整。** 根据复现证据评估任务理解、来源选择、多步工具循环、必要澄清、上下文续接、答案组织、流式反馈和错误恢复。正常范围内的问题应在一次提交中完成必要工具步骤，缺少信息时只问必要问题，不把半成品当完成。保持简洁输入区和连续阅读位置。
4. **以真实目标问题验收，再做防回归。** 至少覆盖成绩总览、指定课程/学期、培养依据、身份普通交流及失败恢复；标明真实来源能否支持预期结论。成绩题需核对实际来源行/统计/范围，不能只断言completed；推理题需看到真实模型实际返回字段在真实页面出现；工具题需对照真正发生的调用及结果，不能只看到“正在思考”。无字段时如实提示并验证模式，不伪造。
5. **最后才收口。** 运行与改动风险相称的回归、实际页面和真实调用验证，分别记录工程、模型协议、来源事实、答案语义和用户验收。只改静态文件优先刷新；确需后端重启时说明学校内存会话会清理。不要用测试数量替代本人场景成功，也不要未经要求commit/push或创建新侧栏任务。

下一轮应输出：失败根因与证据、实施范围、真实页面/问答验证结果、尚未解决的边界及启动方式。新框架、Embedding或任意脚本执行并非预设必要方案。
