# 培养方案约束的模拟学生数据

本批按用户选择，优先覆盖商务大数据分析（信息管理与信息系统—统计学）和统计学，各生成大一、大二、大三三个阶段，共6个隔离样本。用途是测试不同修读进度下的成绩解释、后续课程建议、模块缺口与未知条件处理。

当前产物为**离线数据集与核对页面**，未接入18875学校账号页面，也未用这些样本运行新的模型对话。不修改真实账户、成绩、培养绑定或学校登录。核对页不是另一个Agent服务。

## 数据入口

- 最终核对页：`local-only/curriculum_scenarios_20261024/v4/index.html`。
- 全部数据：同目录`scenarios.json`；另有6个`SYN-*.json`单学生文件。
- 文件摘要：同目录`manifest.json`。
- 方案审核配置：`local-only/curriculum_scenarios_20261024/review.json`。
- 本机预览：`http://127.0.0.1:18879/`，仅静态文件；页面可切换学生、展开成绩记录并下载JSON。

所有培养方案派生行与模拟记录均置于Git忽略的`local-only/`。可提交的内容只有通用生成器、纯合成测试、说明与去敏回执。原PDF、inputs、真实个人数据库及历史失败不改。

## 时间与数据含义

采用两份已有的**2026级培养方案**，分别模拟该批学生推进到各学年的“秋冬结束、春夏选课前”。这是同一培养版本的阶段快照，不是把2026级方案套给当前真实的2024、2025级学生。

## 约束如何落实

1. 从两份PDF的课程设置表提取69与52条课程，共121条。每条保留PDF摘要、物理页、行坐标、原单元格、课程号、学分与建议学期；8个课程表页面已人工视觉核对。正文与跨页要求另核对应原文。
2. 按各自方案分配模块。必修清单的学分和必须与审核配置一致；选修仅从该模块原课程池明确选择，完整模拟路径达到该模块学分下限。个性修读选择本专业进阶路径，不叠加跨专业或自主路径。未选择的课程继续保存。
3. 按原建议学年学期安排。该阶段尚未结束的春夏、短学期及后续年级课程保持未完成；多种建议学期选第一种是明确的模拟取舍，不改写原文。
4. 成绩为稳定生成的65—95分，标为synthetic；通过状态是场景设定，未伪造学校绩点换算、已获学分认定或毕业资格。相同方案课程在三个阶段的已生成成绩一致。
5. 学分使用Decimal汇总；父子模块不叠加，不根据课程名称互认或跨方案借用代码、学分。
6. 外语分层、体育具体课程、通识分类认定、劳育学时、美育/创新创业/心理健康等认定与二三四课堂分别保留。商务双学位原文未给出的平均绩点阈值保持未知；原毕业总要求保留`168+8`与`139+8`，不减8、不推算完整毕业差额。
7. 建议修读顺序不等于先修规则；未核实完整先修、互认与开课资格，不补造关系。没有生成教学班、教师、余量、周次或考试安排，不能据此声称真实可选课表已通过测试。

## 用于后续Agent测试

每个学生JSON包含：`academic_records`（模拟完成）、`planned_next_term`（春夏计划）、`future_courses`、`unselected_courses`、`named_module_progress`、`unresolved_requirements`及测试问题和预期保护条件。

后续测试入口必须显式选择一个`SYN-*`主体，并在独立工作区接入该文件及对应方案。不能通过修改真实用户身份、把生成文件塞入真实成绩缓存或伪装学校实时响应来切换学生。当前数据格式是隔离场景格式，尚不是学校服务的直接导入协议。

优先测试三类普通问题：成绩概况与明细、下一阶段课程选择、已命名模块差额与未确认要求。判定时应检查是否引用正确方案、是否把未来课程当已修、是否把名义学分当认定学分，以及是否擅自编造先修/开课/毕业结论。数据校验通过不能替代Agent语义验收。

## 重建与验证

```sh
python3 scripts/build_curriculum_scenarios.py \
  --review local-only/curriculum_scenarios_20261024/review.json \
  --output local-only/curriculum_scenarios_20261024/new-version
python3 -m unittest tests.test_curriculum_scenarios -v
```

生成器只读PDF，核对指定摘要、课程行数、源文引用和模块选择，再输出新目录；拒绝覆盖已有版本，输出限制在`local-only/`。不访问学校或模型，不激活原23条待审核规则。

12项合成测试通过，覆盖跨方案绑定、课程名/学分/来源篡改、未来课程提前完成、学期倒填、重行/漏行、错误汇总、伪造未知条件及PDF水印过滤。最终9个文件独立重建逐字节一致；实际页面逐一切换6名学生，与JSON数量和学分一致。本轮未重跑全套业务测试；正式培养适用、完整规则与新Agent对话仍未验收。

## 登录后使用真实 Agent（第107节）

模拟问答入口为 `http://127.0.0.1:18880/`，静态数据核对页仍为18879。账号 `business1/business2/business3` 对应商务大数据分析大一/大二/大三，`stats1/stats2/stats3` 对应统计学三个阶段。专用测试密码和账号说明只在 Git 忽略的 `local-only/curriculum_scenarios_20261024/accounts/测试账号.txt`。这些是本地模拟账号，不是学校认证，不使用用户学校密码。

服务端固定账号→学生→培养方案绑定，启动校验数据摘要及课程阶段。模型或HTTP请求不能指定另一个学生。账号验证使用PBKDF2摘要；会话、连续问答与模型思考设置在内存中，刷新可保留当前会话，退出/过期/服务重启后不承诺恢复；详细测试运行证据另存该目录的runs，不作为学校会话或前台历史。

```sh
python3 -m course_assistant.scenario_accounts \
  --bundle local-only/curriculum_scenarios_20261024/v4/scenarios.json \
  --accounts local-only/curriculum_scenarios_20261024/accounts/accounts.json \
  --port 18880
```

只有首次创建新账号配置时追加 `--init-accounts`，已有文件拒绝覆盖。此入口仅监听127.0.0.1，使用独立Cookie及运行目录，不打开18875学校账户库或建立学校网络客户端。`.env`配置沿现有模型读取器，只调用deepseek-flash，默认思考开启；点击发送才运行问答。

前端直接使用现有 `web/index.html` 页面框架与 `web/styles.css`，只将脚本路由替换为 `web/scenario.js` 以连接隔离的模拟接口。配色、侧栏、对话气泡、输入框、模型选择及思考按钮沿原设计，没有另一份主题CSS。学校入口的app.js及运行进程不因此替换。模拟入口当前不含“我的教务”、保存方案或跨登录历史；不把仅复用设计称为已有全部功能。

后台复用 `PersonalDialogueService` 与 `AcademicHarness`，模型自主选择模拟成绩查询、培养及阶段检索，再经现有引用与答案协议校验。模拟工具投影明确标synthetic，实际Flash响应留作本地测试证据，不使用脚本答案。成绩、选修取舍和阶段合计是场景事实；课程名称、学分、模块及建议学期依据原培养资料。没有教学班、周次、节次、已有课表和考试数据，因此本入口暂只能做培养课程与学业问答，不生成可执行无冲突课表。

验证：15项账号/隔离/HTTP专项、12项数据测试及43项对话/Harness共70项通过；另141项个人对话、Web协议与回答协议回归通过。六账号均实际登录并调用Flash，阶段/条数/名义学分与样本匹配；最终商务大二培养列表→排课缺项追问两轮完成。最终8轮16次Flash返回、1次引用修复；此前3轮中有1轮参数失败，原失败保留。浏览器核对原样式、Enter/Shift+Enter、刷新保留、退出和跨专业切换。未运行全套工程，不升级完整语义、正式培养适用/推荐或用户验收。
