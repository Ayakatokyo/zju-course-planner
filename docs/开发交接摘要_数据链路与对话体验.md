# 开发交接摘要：本人数据链路、Agent 对话体验与整体验收

整理日期：2026-10-16（Asia/Shanghai）。项目：浙江大学选课助手，工作区为当前仓库，应用版本0.2.0。本文件总结“12｜本人 Agent 数据链路与对话体验优化”对话，并作为下一对话的优先入口。旧交接保留历史证据；当前状态以本文件、[开发进度](开发进度.md)第64—65节及实际代码/运行页为准。

## 1. 当前结论与用户最新意图

用户认为整个系统和对话仅勉强能运行，效果和体验仍不理想。此前要求先复现真实失败，沿来源准备、检索、模型工具循环、可见推理及前端展示定位；随后要求从数据角度检查RAG是否混乱。用户最新明确：**本地依赖只保留课程信息，其他教务事实通过教务接口取得；其余按检查结果实施优化。** 本轮已实施并启用，但完整体验尚未获得用户验收。

这不是“全部功能已完成，只需刷新”的交接。工程回归、实际模型/学校调用、有限事实支持、完整答案语义和用户验收必须分开。下一轮继续优化整个项目，先明确真实用户任务和当前失败，不以更换框架、加Embedding、增加说明文字或放开任意脚本作为预设答案。

## 2. 必须保留的产品与数据决定

- 学校本人直接登录、教务取数和教务展示已获用户验收并设计收口；沿用直接Python客户端，不恢复浏览器扩展/配对路线。正式学校应用SSO许可仍单独未确认。
- 直接自然语言对话是主入口。不要把查询表单、快照选择或手动prepare按钮放回对话页，也不要要求先去教务页面准备普通问答的数据。
- 用户已允许点击发送时向DeepSeek提交问题和必要相关资料。保留服务端本人授权、出站字段及策略版本检查，不重新加入发送授权勾选或对话设置。模型选择紧邻发送，深度思考为可点亮的独立按钮。
- 答案底部只保留一个默认收起的“查看依据”；实际引用优先，其他命中及整页上下文折叠。实际运行详情放在上方处理过程，运行中展开、终态收起并尊重手动选择；历史按需载入。对话独立滚动、输入区可访问，保留上下翻页和回到最新。
- 本地课程参考只提供名称、代码等来源信息，不因此证明当前开课、名额、稳定课程身份或本人资格。本人教务事实按当轮接口取证；旧快照、PDF和索引仅作私有证据与派生缓存，失败不得回退成“最新”。偏好、锁定、会话和方案等应用状态仍可本机持久化，与教务事实的权威来源分开。
- 本人/realm/连接代次隔离、来源签名/hash和原始记录不可变继续有效；不随意合并同码多次修读，不用synthetic补真实未知。修读实例、课程身份、完成状态、认定归属、页面已选及正式中选必须区分。
- 原inputs不可改写；23条候选规则继续待审。个人原件、截图、问题全文、运行数据库、导出、精确来源定位及凭据不进入Git，私有仓库也一样。密码、Cookie、票据只在学校内存会话中，不让用户发到聊天。
- 实际工具/服务执行、简短处理说明与供应商实际可见推理分开。无可见推理如实提示；不能伪造完整内部思维或未发生的脚本。模型/RAG不得替代权限、规则审核和确定性计算。

## 3. 本轮问题定位与实施

### 3.1 真实问答失败与展示

实际页面复现过工具已完成、DeepSeek已返回推理但最终答复校验失败。增加安全failure_detail、答案拒绝/修复事件；格式/本轮引用问题最多同轮修复一次，只复用既有证据，不重跑采集或工具。权限、敏感内容、越界、HTTP失败和预算耗尽不自动重试。

增加受服务端当前conversation绑定的上一轮诊断工具，不接受模型任意指定run。诊断只投影实际状态、工具种类、数量和安全错误，不能当作答案正确性证明。全匹配行完成状态known/unknown聚合独立引用，自动主修来源不能写成用户指定；每结论最多15个引用，修复不能靠删掉有效引用过关。依据入口和过程区按用户截图精简。

### 3.2 数据体检结论

未发现当前本人对话混检旧54块参考、synthetic、R3首片或整批离线培养PDF。主要问题是来源复用、采集截断、工具契约、字段/范围语义、培养分块和模型证据分配，不能简单归因于“向量库里混了所有东西”。离线课程库、R3、本人的结构化观察与本人培养索引是不同入口。

旧默认最多3页导致真实来源只读60/104；prepare已有对应scope就跳过，不核partial或新鲜度。records本机API能续取，但模型工具仅前15条；同学年scope内行字段未知时再传year可误筛成0。培养按词法/字符块召回，所问模块top5曾有4条其他模块；统一6000字符证据预算存在工具顺序偏置。来源版本变化或历史超限会重置模型上下文。检查原件、独立探针和真实失败的证据分母分别记录，不能互相替代。

### 3.3 当前v5实现

- 每轮来源准备强制教务读取，记录/培养工具固定当轮成功新回执；同轮同scope复用，下一轮重新读取。默认最多50页×20条、单来源60秒，预算/异常仍明确partial。明确学年/季节和跨scope查询可表达，有歧义或无法核实相对学期则澄清；来源scope可辅助匹配未知行年份，不修改原值。
- records支持summary与records，前者独立计算所有匹配行的聚合，后者通过本轮opaque PAGE token续取。真实cursor/观察编号不发模型，伪造及跨参数续取拒绝；遗漏投影时不越过未发送行。来源绩点按原值允许投影，不自行计算正式GPA或已获学分。
- 本地课程参考从显式delivery index读取，核manifest/hash/计数及目录边界；只取课程名称/代码参考，不加载整包个人页面或培养资料，无隐式synthetic回退。当前配置库为2177个课程代码组，不是当前完整开课或本人可选池。
- 培养保留原页/连续span，派生保守去水印model_text和精确保留spans；按模块、表头、课程行、附注、跨页关系组织，正文片段≤1800字符。有界model_context与整页上下文分开，按实际遗漏标记。旧索引重建，旧连接引用不复活；仍为精确/词法检索，未接Embedding。
- 模型证据按类型独立限额，总额为各桶之和，成绩不能占满培养桶。每轮旧用户意图只作为system中的已结束指代说明，当前唯一user；旧答案、工具事实和推理不重发。纯目录任务不声明个人记录/培养工具，运行时拒绝未声明调用，避免重复历史任务。
- 动态读取在连接锁内先核严格版本，仅接纳本轮自己的新来源；外部并发变化和撤权仍拒绝。工具契约为personal-question-tools-v5-live-sources，模型循环最多8步、10工具、160000 UTF-8字节和120秒。来源准备另有预算，不能把120秒称为整个HTTP请求的统一上限；超长明细及多scope延迟仍需真实评估。

## 5. 未解决问题及取证限制

1. 63条成绩未知的上游原因未查明。持久化业务投影中缺少注册成绩别名，解析未知数量一致，未见“已持久化有值而被解析丢弃”；缺原始HTTP正文及该字段的预投影诊断，不能说学校原接口必然没值。后续如查此问题，针对具体字段采安全presence/类型/数量诊断，不打印凭据或整份原始响应。
2. 原始remote模型消息在后续轮会重建，未逐轮另外归档。已留存local投影、引用、来源及事件，不得把事后重投影称为当时逐字节HTTP出站核验；一次组合投影仅曾观察、未存原始wire。需要更精确取证时先设计最小私有审计字段和保留期限，不能默认把所有个人协议正文写常规日志。
3. 培养规则、正式本人适用绑定、修读认定、重复政策、完整教学班/时段/余量及可执行校历仍是实际推荐依赖。用户希望其他事实走接口，不意味着所有需要的接口都已确认或接通；现有已注册学校能力和待发现来源分开。
4. 全部自由文本语义未验收。模型仍可能使用实现名、过量边界说明或含混指代；不能只校验JSON/引用存在就宣称答案正确。应以真实自然问题及明确期望支持集合审阅，不只加特定问句prompt或正则。
5. 实际课表、考试、模型多页续取、相对学期、多学期比较和长任务未在本轮新做真实页面验收；工程覆盖不能替代这些真实任务。长清单受循环、证据与时间预算，不能保证任意组合一次列全。
6. 中途一条旧终态过程曾观察到重新展开，未取得触发归因；代码未见下一轮统一展开逻辑，刷新历史后全部折叠。不宣称该现象已定位或修复；复现时核对独立process key、真实阶段和手动选择。
7. 真实推荐仍受real_recommendation_not_ready保护，不能为了表面出方案删除保护。R0—R2合成推荐、历史、锁定、确定性计算及保存导出可复用；R3独立本机参考不是当前本人的正式推荐。Embedding、任意终端脚本、全校更新或选退课未新增。

## 6. 核心入口与当前实际链路

```text
/api/chat/turn → 本人/连接/策略/模型版本验证
  → personal_acquisition：按当轮请求取得学校来源回执
  → personal_dialogue：get_my_context服务预检
  → DeepSeek选择受限领域工具 → 本机执行/必要补读
  → 白名单字段、按类预算、签名引用投影
  → 结构化答案及引用校验（必要时同轮一次格式修复）
  → 私有会话/事件与结果保存
/api/chat/progress：实际阶段及SSE可见推理
/api/chat/run：同本人运行详情，历史按需读取
```

## 7. 下一轮优化整个项目的建议顺序

1. 先核对当前Git、服务与资产版本，读取本文件和进度。保留登录现场；若有用户新失败，先拿到当轮任务、预期来源、实际工具参数/返回及最终答复，不先重复旧修复。
2. 用一小组真实常用任务覆盖成绩概况、具体课程、学期/跨学期、培养条款、来源不足和连续追问，分别核来源选择、充分证据、未知归因、任务完成率、时延与答案可读性。把保留问题和预期支持集合冻结，人审与自动检查分开。
3. 优先补数据/任务契约：成绩未知的上游字段诊断、明确/相对学期的可靠来源、同名/同码课程观察连接、规则与本人适用审核。不要把“检索命中”“字段非空”提升为认定。
4. 优化任务规划、必要澄清、工具续取、总预算/失败恢复和多轮指代，使普通需求一次提交尽可能完成；页面只展示与任务有用的简短进度、真实轨迹与可折叠依据。
5. 在真实输入依赖满足后接通“对话→多套具体课表→比较/锁定/连续调整→保存/导出”。复用确定性计算；缺依赖明确unknown或not_ready，按切片验收而不是一次开放全部动作。
6. 对同一批问题再决定词法、向量或混合检索的必要性，比较召回及必要上下文覆盖。按风险做工程、真实调用、语义与页面验证，最后单独请用户验收。

这是一份接续建议，不是自动授权扩大到全校采集、改写原inputs、外部发布、任意脚本执行或选退课。
