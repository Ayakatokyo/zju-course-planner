# 课程池与板块重叠核验（2026-10-13）

用户补充业务事实：各账号总体面对相同的课程池，专业基础、本类专业等涉及专业的板块会有不同展示。后续按“统一课程/班次底库＋带上下文的板块关系＋培养方案要求＋本人状态”建模，不把每个账号当作独立课程本体库，不为开始RAG再采其他账号。

本轮只读核对后端已采秋冬批次的课程分类关系、课程代码分组和班次观察。用户的整体课程池说明作为业务前提；以下数字是本批次跨板块交集实算结果，不声称进行了多账号对照。

“所有类（专业）”包含本批次中很多其他板块的课程，但并非全部课程池。通识选修与体育在本批次均未与其课程代码集合重叠；因此此前采集多个入口仍有必要。

## 2. 班次重叠

6,187条班次观察按本批次来源班次键聚为4,715组，其中1,373组在多个板块出现，多出1,472次观察。这解释了班行观察数大于来源键组数。课程重叠不自动证明两入口返回的班次集合或动态余量完全一致，原观察/筛选/时间继续保留。

来源键跨刷新稳定性尚未验证；5组既有候选冲突也不能靠同键或最新时间自动消解。本轮没有把来源键组直接确认为永久教学班身份。

## 3. 数据与RAG设计调整

1. 课程基础事实按课程身份归并，保留代码体系、字段版本和来源。已有courses按代码分组并留variants，不依据相同名称合并。
2. 板块出现用多对多关系保存，带学期、专业/方案筛选和观察版本。已有classification_memberships已单独保存此关系；同课程跨板块只需一份实体，不重复推荐或人为增加向量检索权重。
3. “某专业必修/计入某模块”来自培养方案版本—要求节点—课程关系，不把当前板块或category_raw/nature_raw提升为课程全局属性。原字段可作为来源范围内的性质观察。
4. 当期班次按候选身份聚合多次观察，时段、考试、余量分别管理；可查询统一底库，动态状态保留时间。本人页面已选等状态单独授权，课程原观察中的个人状态标志不能直接进入共享课程投影。
5. RAG检索培养要求时按方案/年级/路径/版本过滤；查询课程存在、班次与时间使用统一结构化底库及分类关系。某门课在不同专业的要求不同，不能因底库共享而合并要求条款。

当前“账号可见”描述取得数据的来源证据；不再用它把公共课程事实整体设计成按账号重复存储的知识库。本人选课资格、学业事实与授权继续独立处理。

已保存本机统计回执及四份输入的SHA-256，校验分类出现总和与课程分组数量一致。原始数据、规范化候选与应用未修改，无新学校请求、模型调用或回归测试；本轮仅统计与设计更新，未提交推送部署。
