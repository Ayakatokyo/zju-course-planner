# 学生教务问答与选课推荐总体设计 v2

日期：2026-10-16（Asia/Shanghai）。产品名称：**浙大教务助手**。状态：按用户最新决定更新的定位与实施设计，不代表所列能力已全部实现。

## 1. 定位与两条核心能力线

用户认可此前的体验优化方向，将系统从以对话推荐课表为目标扩大为覆盖学生本人教务信息的问答Agent，并明确对话式课程和课表推荐必须保留完善；随后确认名称“浙大教务助手”。

整体定位：通过自然对话查询、核对和解释获授权的本人教务信息，并完成课程与课表的推荐、比较、锁定及连续调整。教务问答与对话式推荐共用入口和基础设施，分别验收。推荐不等待所有问答领域完成，信息覆盖扩大也不能使推荐无限后移。

## 2. 信息领域与任务

| 领域 | 目标任务 | 当前基础及边界 |
| --- | --- | --- |
| 本人资料 | 核对已知学业背景、来源及可查询范围 | 已有可信学校本人连接；只使用获准字段，不要求自报身份来授权 |
| 成绩与修读 | 概况、课程明细、学期比较、重复观察和未知原因说明 | 有当轮查询、聚合与受限续页；稳定修读、认定及正式GPA尚未充分核实 |
| 课表与安排 | 按学期/课程/时间/地点查询和比较，说明已知冲突 | 有本人课表观察；缺周次或可靠校历时不推断真实日期、完全空闲 |
| 考试 | 核对明确学期/季节的时间地点及相关冲突 | 有注册查询；相对时间须可信基准，不能按日期猜学期 |
| 培养资料 | 解释模块、表头、课程行、附注和例外；条件充分时算局部贡献/缺口 | 有当轮PDF与候选语义块；Embedding、完整上下文、适用及规则审核待完善 |
| 课程与教学班 | 查询名称/代码，定位候选及目标学期班次 | 本地课程参考已接通；完整候选/余量/资格来源未确认，不以名称证明身份或可选 |
| 选课与课表方案 | 按修读目标选择课程、选班、比较方案并持续调整 | 合成底座已实现；真实输入/规则/产物契约需独立接通 |

共用任务包括查询、概括、比较、解释、来源核对、澄清及持续追问。新领域先登记需求、可信来源、最小范围与授权方式；“覆盖本人教务信息”是产品目标，不是本轮全量采集指令或已覆盖全部学校信息的声明。

## 3. 完整用户旅程

**教务问答：** 提问 → 确定任务/范围 → 必要澄清 → 当轮取证 → 结构查询或资料检索 → 必要证据核对 → 答复及来源 → 追问/比较/话题切换/失败恢复。范围与来源名称、数值、必要条件、自由文本支持和任务完成都要检查；引用存在不等于语义正确。

**选课与课表推荐：** 表达目标 → 核对本人情况、适用要求及已有安排 → 澄清硬/软条件和锁定对象 → 确认限定候选课程/班次 → 确定性搜索与逐套复核 → 差异方案和取舍 → 比较/锁定/换课/换班 → 保留条件重新计算 → 明确保存/导出。

课程查询、条款介绍或文字建议不能代替推荐旅程。方案数由解集决定，不补造候选凑数量；资料不足、范围内无解、条件性参考和预算截断分别报告，实际选退课仍由用户在学校系统完成。

## 4. 共用架构

```text
自然语言 + 本人任务状态
  → 受限任务计划 + 服务端范围/权限校验
  → 本轮来源协调和实际回执
     ├─ 结构化教务查询、聚合与比较
     ├─ 当前培养资料的词法/向量混合检索（待实施）
     └─ 输入充分后的确定性学业计算、课程选择与排课
  → 带范围、版本、未知及出处的证据/计算结果
  → 答案语义与任务完成核对
  → 答复、实际过程、方案及后续调整
```

统一任务目标、澄清槽位、来源范围、业务事实、必要证据和版本化结果等逻辑契约，不要求一对象一张表或一次重构全部代码。模型理解需求、选工具并解释；服务端决定身份/授权、范围和实际执行；确定性工具负责统计与计算，不能让模型自行认定。

任务状态需区分当前任务、已结束任务和明确未完成事项，支持澄清、部分完成、失败恢复及对象选择。旧事实、方案或PAGE不会因为任务持久化而成为本轮有效结果；变化后重新取证或校验。

前端保留统一对话、“我的教务”辅助查看、单依据入口、真实过程及现有输入偏好。仅补任务必需的澄清、进度、恢复与方案控制，不恢复快照选择、手动prepare或发送勾选，不伪造思维/脚本。

## 5. 数据与能力准入

保留已验收的学校直接登录/本人取数及本人、realm、连接代次、出站字段与策略检查。只有课程参考依赖本地，其他教务事实按轮从获准接口取得；快照、PDF与索引只是私有证据及派生缓存，失败不回退最新。

未来向量可按同一规范文本和编码器版本复用计算，但须先取得本轮成功回执并重新绑定引用和权限。成绩/课表/考试清单和统计走结构化查询，向量不替代身份映射、认定或规则审核。

推荐依赖分别登记稳定课程/修读/班次身份、本人培养适用和审核规则、修读/认定/重复政策、限定候选/资格/余量、完整时段/周次/考试/校历和固定安排、真实草案冻结及导出契约。每项说明现有入口、缺口、关闭方式和验证证据，不长期只写“真实推荐未就绪”。

可先做好事实问答及原文解释，再按条件开放限定候选比较或明确条件性参考；相应依赖充分后才计算指定范围缺口或给已验证推荐。保存的是草案，不能称正式中选；可靠日期不足时不生成伪准确ICS。原inputs和候选规则保留，synthetic隔离。新增来源、扩采、外部发布或选退课继续单独授权。

## 6. 双线里程碑

| 阶段 | 教务问答交付 | 选课/课表推荐交付 | 验收门槛 |
| --- | --- | --- | --- |
| M0 语义与评估 | 固定常用任务/保留题，统一范围与来源表达 | 固定一个明确学期的限定推荐切片及依赖关闭清单 | 支持集合、允许结论、未知和完成条件明确；推荐有具体下一产物 |
| M1 证据与业务输入 | 本轮PDF模块核对及词法/dense/混合对照，结构查询/比较完善 | 课程/修读/要求映射、审核规则首片与获准来源下的候选输入适配 | 必要条件不遗漏；输入有来源/状态/版本；重复修读不误合并 |
| M2 连续任务与规划 | 澄清、长清单、话题切换、恢复、总预算与可读性 | 前提充分后生成限定方案，比较/锁定/调整并重算 | 不丢任务、不重复/漏项却称完成；每套方案独立复核且保留硬条件 |
| M3 完整旅程 | 已支持领域真实旅程、窄屏/键盘/恢复体验 | 本人草案保存、历史、失效重校验及导出完整闭环 | 两线分别报告工程、真实调用、有限支持、完整语义及用户验收 |
| 后续扩展 | 按需求接新领域和可信来源 | 扩大已验证候选/规则和场景 | 新范围独立验收；新增授权不由产品目标替代 |

每个里程碑检查推荐的实际产物和依赖关闭，不能只持续扩问答领域；单次缺陷修复不强制同时修改两线，避免人为扩改。共同底座与数据依赖可并行推进，具体能力满足门槛即独立验收。
