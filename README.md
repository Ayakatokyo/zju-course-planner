# 浙大教务助手

**用自然语言了解自己的学业情况，把选课想法变成可以比较、持续调整的课程方案。**

浙大教务助手是一个面向浙江大学学生的本地运行 AI 项目。它把本人教务查询、培养资料检索和课程组合计算放进同一个对话入口：你提出问题，助手按需读取相关资料、调用工具，再给出回答或方案。

项目围绕两条核心能力展开：**教务信息问答**与**对话式选课 / 课表规划**。目前已接通本人学校登录与教务数据读取，并在限定历史课程数据上走通生成、锁定、调整和比较的部分真实对话流程；正式选课推荐仍在完善中。

## 为什么做这个项目

一次选课决策往往需要同时核对成绩、培养要求、课程信息和时间安排。信息分散在不同页面和文档里，条件一变，又要重新比较。

这个项目希望减少三类重复工作：

| 学生要完成的事 | 助手提供的帮助 |
| --- | --- |
| 弄清自己的成绩与安排 | 在对话中查询、追问和解释本人记录；也可从侧栏打开成绩、课表或考试页面核对 |
| 看懂培养资料中的要求 | 检索相关课程行、模块和附注，辅助理解原文，保留尚不能确认的适用条件 |
| 在学分与时间偏好之间做选择 | 计算多套课程组合，比较差异；锁定想保留的课程后，继续调整其他条件 |

它的业务价值在于把“找资料、核对条件、比较方案”连接起来。目前尚未量化验证节省时间或决策质量的提升。

## 怎么使用

### 1. 登录并查看自己的教务信息

启动学校模式后，在本机页面完成学校账号登录。从左侧进入“培养进度”“成绩记录”“我的课表”“考试安排”或“当前选课”，分别核对对应信息。成绩仅按所选学期展示，课表和考试各自保留学期选择，各页独立查看主要数据。

回到“对话”，直接表达需求，例如：

> 帮我看看我的主修成绩概况。
>
> 列出刚才提到的这门课的成绩明细。
>
> 培养方案里，专业选修部分有哪些要求？

明确学年、学期或课程名称，有助于缩小查询范围。来源缺项、学校会话失效或暂时无法核实的内容会影响回答；查不到不能直接理解为没有记录。

### 2. 从一个选课目标开始

在已配置并获准使用历史课程数据的环境中，可以尝试下面的连续对话。这里演示的是**指定学期历史课程之间的组合测试**，不代表学校当前可选课程，也不判断与本人已有课表的冲突：

> 在已配置的 2026—2027 秋冬历史课程范围内，选 3 门、至少 6 学分，尽量周五空闲。只比较这些课程之间的组合。

拿到方案后，可以继续说：

> 锁定方案 A 中的【课程名称】，其他范围和学分要求保持不变，把周五改为必须空闲。
>
> 比较调整后的 A、B 两套方案，告诉我课程和时间安排有什么不同。
>
> 只解释为什么这套方案超过了 6 学分，不重新生成。

将【课程名称】替换为实际返回的课程；有多个班次时明确班次。“尽量”表达偏好，“必须”表达硬条件。系统会在调整时保留已有锁定和明确条件并重新计算；条件无解或数据不完整时，需要澄清或补齐信息。

### 3. 核对结果，再决定如何选课

回答以结论、方案和选择理由为主；左侧教务功能页用于查看来源记录。模型选择和深度思考按钮位于输入区，点击发送后才调用模型。

真实测试已支持部分连续问答与方案调整，但回答仍可能出现过度推断、范围概括不准确或文字偏长。涉及培养认定、可选资格、余量及最终时间安排时，请回到学校系统核对。**本项目不自动选课或退课。**

## 本地启动

基础服务需要 **Python 3.10+**，使用 Python 标准库、SQLite 和原生网页，无需前端构建。可选的本地语义检索另需编码器环境。

在仓库根目录操作。先参照 [.env.example](.env.example) 创建本机 `.env`，填入自己的 API Key；已有配置请直接编辑，避免覆盖：

```dotenv
DEEPSEEK_API_KEY=你的_API_Key
DEEPSEEK_MODEL=deepseek-flash
COURSE_ALLOW_REFERENCE_TEXT=false
```

Key 仅留在本机配置中。未配置模型时可以查看界面；学校模式仍可使用教务查询页面，但不会得到真实 AI 对话回答。

### 使用 ChatGPT 订阅或调整思考强度

可在输入框旁的模型菜单选择 **Continue with ChatGPT…**，在 OpenAI 官方页面完成登录及订阅额度授权。应用通过官方 Sign in with ChatGPT 本地客户端流程接入，动态读取此账户实际开放的模型；不是把 ChatGPT 网页全部型号固定写进菜单，也不转换为普通 API 余额。此类调用会计入 ChatGPT Work 与 Codex 的共享用量，减少可用于 Codex 的额度；可在 ChatGPT「设置 → 用量 → 应用限额」为本应用设置每周上限，这不是独立额度池。DeepSeek 调用不消耗这份额度。当前官方预览的账户、模型和共享额度限制仍适用。

首次启用需在运行主应用的同一 Python 环境安装可选签名校验依赖：

```sh
python3 -m pip install --target private/chatgpt_runtime/site-packages -r requirements-chatgpt.txt
```

若使用隔离环境，也可直接安装到该环境。然后启动/重启主应用。学校登录只负责本人教务数据权限，ChatGPT 登录只负责模型调用。授权凭据按教务助手账号隔离，保存在运行数据库同级的 `chatgpt/` 私有目录，目录权限 0700、文件 0600，自动续期；不进入浏览器存储或 Git。请勿复制该目录到共享位置。主应用重启会清除学校内存登录，需要重新登录学校。

授权成功后会读取模型目录，按本项目当前偏好选择 GPT-6-Luna；目录未提供该型号时提示手动选择，不自动切到其他 GPT。发送按钮旁的模型菜单内，模型和推理等级分成两行；外部显示当前模型及等级，左侧保留深度思考开关。可选思考强度：DeepSeek 当前支持 low（低）/high（高）/max（最高）；GPT 仅显示目录实际声明的档位，未声明时使用模型默认，不虚构可用强度。不支持关闭思考的型号会禁用开关。更改模型或强度会更新出站版本，正在执行的旧版本结果不能混入新轮次。授权/刷新目录/调整强度不发送教务问题；点击发送才开始模型推理。

模型菜单支持重新连接或断开 ChatGPT。断开会尝试远端撤销并移除本机凭据；网络失败时明确提示远端撤销未确认。授权撤销、续期失败或共享额度耗尽会如实报错，不自动改走其他供应商。官方资料：[注册与登录](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[模型与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)、[预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

### 用自己的学校账号查询

```sh
python3 -m course_assistant.server --enable-school --port 18875
```

打开 [本机教务助手](http://127.0.0.1:18875/)，完成登录后使用“对话”或左侧教务功能页。验证码由本人输入。学校模式默认将运行数据保存在 Git 忽略的 `private/` 目录。

**课程组合测试需要额外的本地数据配置。** 仓库不附带真实个人资料、受限课程数据或本地编码器；仅运行上述命令不会自动获得历史班次。配置方法见[本地运行与开发指南](docs/本地运行与开发指南.md)。

### 已配置持久向量库的本机环境

使用统一启动入口保留Qdrant服务端和登录异步准备：

```sh
python3 scripts/run_vector_app.py --enable-school --port 18875
```

该入口需要本机已有模型、OCR语言文件和Qdrant服务配置，不随仓库分发。2023—2026级只复用已有向量，其他已知年级检查缺项后才增量入库；本人权限及每轮学校核验保留。安装、迁移与缺项状态见[培养方案向量库运行指南](docs/培养方案向量库运行指南.md)。

### 没有学校账号，先体验合成演示

配置模拟学生资料后，模拟账号与学校账号使用同一个登录入口、对话和教务功能页。服务端按账号选择数据提供层：学校账号从教务接口取数，模拟账号从本机审核资料取数；之后共用 Agent、Harness、记录查询和培养 PDF 检索。界面仅标明“模拟数据”，身份、会话和资料仍按账号隔离。配置见[本地运行与开发指南](docs/本地运行与开发指南.md#统一登录中的模拟账号)。原独立模拟服务保留为历史测试入口，不再作为主产品入口；现有模拟资料未提供实际教学班或课表，不能据此求解真实排课。

```sh
python3 -m course_assistant.server --enable-mock --recommendation-demo --port 18865 --db runtime/recommendation_demo.sqlite3
```

打开 [本机推荐演示](http://127.0.0.1:18865/)，选择“模拟学生 A”或“模拟学生 B”，按页面提示允许发送合成测试需求，再输入：

> 优先补专业选修 6 学分，偏向 AI，尽量周五空闲，保留体育。

可以体验推荐、比较、锁定调整，以及演示方案的保存与导出。**演示使用虚构身份和固定数据**；这些保存 / 导出能力不代表学校本人分支已开放相同功能。对话同样需要可用的模型 API 配置。

服务仅监听本机 `127.0.0.1`。终端按 `Ctrl+C` 停止。已有服务正在使用时直接打开对应地址，避免重复启动；本项目尚未作为公网多用户服务交付。

## 当前能做到哪一步

| 能力 | 当前状态 |
| --- | --- |
| 学校登录与本人教务查看 | 直接登录、本人取数及教务展示已取得用户验收；来源缺失仍保留未知 |
| 教务问答与培养资料检索 | 已接入真实模型和受控工具，部分本人问答经过有限核对；完整语义准确性仍待验收 |
| 课程组合生成、锁定、调整与比较 | 已在获准学期的历史班次上取得有限执行支持；不证明最新开课、本人资格或正式培养适用 |
| 保存与导出 | 独立合成演示可用；学校本人条件测试尚未开放相同交付能力 |
| 正式推荐与线上服务 | 完整规则认定、真实推荐及整体用户体验仍待验收；公开部署和并发治理处于规划阶段 |

工程测试、真实模型调用、来源核对和用户验收分别记录。详细结果与已知失败见[开发进度](docs/开发进度.md)，不以测试数量替代产品完成度。

## 数据与隐私

本人范围由服务端验证的学校登录确定；模拟身份只访问合成数据。密码、学校 Cookie 和票据仅在内存中处理，不写入仓库或业务日志；个人记录、培养 PDF、对话与派生索引保存在本地私有目录。

**本地运行不等于模型离线运行。** 学校模式下点击发送，会把问题及必要的相关记录、培养片段交给配置的 DeepSeek 模型；学校凭据、完整 PDF 和本机来源路径不进入模型。`.env` 中的 `COURSE_ALLOW_REFERENCE_TEXT` 控制独立参考分支的非个人原文发送，不是本人对话的总开关。不要提交真实截图、个人导出、运行数据库或任何凭据。

## 它如何工作

模型负责理解需求、选择已声明的工具和组织答案；程序负责身份权限、数据读取、学分与时间条件计算，以及引用和方案版本检查。

```text
提问或追问 → 理解任务 → 按需查询 / 检索 / 计算 → 回答与方案
                            ↑                     │
                            └── 保留条件，继续调整 ──┘
```

技术实现采用单 Python 服务、SQLite、原生 HTML/CSS/JavaScript、DeepSeek 工具调用，以及本地词法 / 可选语义检索。模块分工见[执行流程](docs/本地运行与开发指南.md#执行流程)。
